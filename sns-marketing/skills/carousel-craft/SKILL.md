# carousel-craft — 良いカルーセル画像を作る

縦長カルーセル画像（TikTok 1080×1920 / Lemon8 1080×1440）を、スクロールを止め・完読され・保存される質に引き上げるためのスキル。
**hioto / tone / anki / connect すべて共通**。生成エンジンは各 repo の `post/build_posts.py`、オーケストレーションは `sns-daily-pipeline/scripts/gen.py`。

## このスキルの正本（必読）
- **[[DESIGN_NOTES]]** … ★**毎回読む**。ユーザの確定した設計指摘・好みの蓄積。一般原則と矛盾したら**こちらが優先**。
  新しい指摘・好みをもらったら**必ず1行追記**して育てる（これが「指摘をちゃんと管理する」仕組み）。
- **[[PATTERNS]]** … 投稿/スライドの**型カタログ**（投稿アーキタイプ20・フック16・スライド別レイアウト・法令/商標ガード）。企画で**毎回ここから1アーキタイプ＋1フックを選ぶ**（ワンパターン化を避ける）。新しく効く型は追記して育てる。
- **[[LAYOUTS]]** … **配置・グリッド・ゾーン・階層**の正本（要素を画面のどこにどう置くか）。表紙9型/中面7型の配置テンプレ、ゾーン定数、ジャンプ率、整列・写真×文字・一貫性。spec の各スライドはこの配置型に沿わせる。
- **[[SPACING]]** … **余白（ホワイトスペース）**の正本（要素のまわり・あいだの空気の設計）。8の倍数スケール・内側<外側・等間隔中央寄せで**詰め込み/不揃い/間延び**を潰す。実装は `engine/brand.py` の `sp()/snap()/stack_centered()`。余白は素人感の最大要因なので毎回ここで確認。
- **[[DESIGN_SPEC]]** … 良いデザインの一般原則の言語化（フック/タイポ/配色/セーフゾーン/構成/フォント/実画面構図）。数値は**目で判断する物差し**。
- **[[MATERIALS]]** … 全アプリの素材在庫＋specレシピ。アプリ固有の素材/ブランドは各 `target/<app>/material/`（manifest.json＋OVERVIEW.md＋app_icon＋symbols）。
- **engine/ ＋ templates/** … 共通描画ツールキット（`engine/brand.py`）と**雛形**（`templates/standard.py` 等）。画像は使い回さず**雛形から毎回新しく組む**。ブランドは material/manifest.json から。
- **engine/assets/svg/** … 汎用**SVGアセットバンク**(CTA/装飾/アイコン/バッジ/UI部品/矢印・多色/単色)。台帳=`index.json`(名前/概要/タグ)。`paste_svg`で配置(multiはcolor=None)。詳細は [[MATERIALS]] §6。
- `scripts/` … `qa.py`（客観チェック＋コンタクトシート）、`fonts.py`（高インパクト和文フォント）、生成は `sns-daily-pipeline/scripts/gen.py --app <id>`（manifest駆動）。

## 大原則（[[DESIGN_SPEC]] §0 の要約）
1. **素材ファースト**：表紙を含む全スライドに実素材を敷く。**ベタ塗り/グラデだけのスライドを作らない**（最重要・最大の弱点）。
2. **0.5秒で勝負**：表紙はフックに全振り。大きく・上〜中央・1メッセージ・オチは隠す。
3. **1スライド1メッセージ**／**5〜7枚**／最後にCTA。
4. **質はコードで測らない**：可読性・美しさ・フック強度は**エージェントが画像を見て**判断する。`qa.py` は素材の有無とセーフゾーンを描くだけの補助。

## ワークフロー（spec → 生成 → 目視レビュー → 修正 を回す）

### 0. まず [[DESIGN_NOTES]] を読む
ユーザの確定した好み・指摘（CTAは検索誘導・実画面は見切れ・小さい文字は書かない…）を頭に入れてから企画する。
**この回でユーザから新しい指摘が出たら、作業の最後に [[DESIGN_NOTES]] へ1行追記する**（日付・対象・指示・対応）。

### 1. 企画
**[[PATTERNS]] から「投稿アーキタイプ1つ＋フック1つ」を選ぶ**（過去と被らせない）。それを [[DESIGN_SPEC]] §2,§6 とアプリの `material/OVERVIEW.md`（concept/コンテンツ知識）に沿って具体化し、各スライドの中身を決める。表紙はオチを言わない。実アプリ宣伝なら [[PATTERNS]] §5 の法令ガード（**薬機法の効能標榜**・No.1/効果断定・打消し表示・「App Store」表記）を必ず守る。

**枚数は 3枚 or 6〜9枚**（★2026-07-25 実測改訂）。**4〜5枚は最も弱い谷**なので避ける ——
自前クロール1,087件・TikTok公式「3 or 7-9枚」・Socialinsider 2,200万投稿の**3ソースが独立に同じU字**を示した。
`qa.py` が4〜5枚を警告する。上限は Lemon8 10枚 / IG 20枚（**Graph API経由は10枚**）/ TikTok 35枚。

**単一アプリを売るなら [[PATTERNS]] §1b の C型／D型から選ぶ**（実物のデッキから起こしたテンプレ）。
アプリ広告の実測（AppsFlyer 110万クリエイティブ）で**チュートリアル/デモ型 > 社会的証明型**（IPM +45%）。
**出力が視覚的に映えるアプリは D型（説明2枚＋成果物5枚・文字ゼロ）が主砲。**

### 2. spec を書く（**素材を全スライドに** ＋ [[LAYOUTS]] の配置に沿う）
[[MATERIALS]] のエンジン別レシピに従い、`spec.json` を書く。各スライドの**配置は [[LAYOUTS]]**（ゾーン定数・配置テンプレ型・ジャンプ率・整列）に沿わせる。**必ず**：
- 表紙 `cover` と `photo` に `bg`（実素材の**repo相対パス**＝ルートバンク or 自前実画面）を入れる。**省略しない**（anki/connect の手続き背景＝灰色、tone のベタ赤を避ける）。
- `shot` を複数枚（そのアプリの実画面）。緑クロマキーがあれば `footage` で世界観差替（hioto/tone）。
- 配色は §4 の70:25:5、見出しは強いウェイト/書体（§3・§8 のフォント表）。

ルートバンク背景の引き方・タグ・各アプリ在庫は [[MATERIALS]] §0,§2。

### 3. 生成
```bash
cd ${CLAUDE_PLUGIN_ROOT}/skills/sns-daily-pipeline/scripts
python3 gen.py --app <hioto|tone|anki|connect> <spec.json> <outdir>
rm -rf <repo>/post/__pycache__ 2>/dev/null
```

### 4. 客観チェック（コード＝補助）
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/skills/carousel-craft/scripts/qa.py <outdir> --spec <spec.json>
```
- `hard_flags>0` なら **spec を直して 2 へ戻る**（exit 非0）。2種類ある：
  - **NO-MATERIAL** ＝ 素材未使用（cover/photo に `bg`、shot に `shot` が無い）
  - ★**LEGAL / BAIT** ＝ 文言が法令・規約に触れる。**薬機法**（「ストレスが減る」「メンタルが整う」
    「自己肯定感が上がる」＝日記/メンタル系アプリが直撃）・**景表法**（No.1・最上級）・
    **engagement bait**（「保存してね」の裸の要求 → 「次に〇〇する時のために保存」と理由を添える）。
    生成後に目で気づくのでは遅いので **spec 段階で止める**。
- `soft_flags`（RIGHT-RAIL/BOTTOM-UI/**DEAD-BAND**＝縦の死に空間/間延び）は目視ヒント。`<outdir>/_qa/<platform>_contact.png` にセーフゾーン枠付き一覧を出力。DEAD-BAND が出たら [[SPACING]] §6 で詰める。
- ★**セーフゾーンは 2026-07-25 に実測値へ改訂**（旧値は 80〜330px 小さかった）。TikTok は
  **下810pxがUI**なので**CTAを下端に置けない**。右レールは y>=840 のみの**L字**。→ [[LAYOUTS]] §2

### 5. 目視レビュー（ここが本体）★必ず実施 — **qaの数値で満足しない・定性で判断する**
qa はセーフゾーンと素材・間延びを機械チェックするだけ。**美しさ・質感・違和感は数値に出ない**。必ず自分の目で見る。
**コンタクトシート `_qa/*_contact.png` ＋ 表紙・info・shot・cta を各1枚 raw PNG で Read**（コンタクトは縮小なので画質・質感は raw で見る）。[[DESIGN_SPEC]]（§2,§5,§7）・[[SPACING]]（§9 余白 / §11 画質）で採点：
- **画質・質感**：フラット面にザラつき（grain誤用）がないか／文字エッジがシャープか／写真grainが細かいfilmか（[[SPACING]]§11）。**等倍〜2倍で1枚確認**。
- **余白の違和感**：左右対称か／番号・アイコンと本文が近接しているか（浮いていないか）／縦の重心が可視帯の中央にあるか／間延び・詰まりがないか（[[SPACING]]§9）。
- 表紙：親指サイズでフックが読めるか／上に死に空間がないか／背景に実素材があるか／オチを割っていないか。
- 全体：実画面が証拠として効いているか／写真上の文字が読めるか（スクリム）／右いいね列・下UIに被っていないか／整列が揃っているか／既存投稿と被っていないか。
- **「なんか変／荒い」と感じたら言語化して原因を特定する**（grain・近接・重心・字面…）。感覚を放置しない。
- ダメなら **spec（文言・素材・配色・レイアウト）または雛形を直して 2〜5 を繰り返す**。納得いくまで回す（1発で終わらせない）。

### 6. 確定
良くなったら本番フロー（[[sns-daily-pipeline]] の予約、または各アプリ sns-post）へ渡す。

## フォント（任意アップグレード）
`python3 scripts/fonts.py` で高インパクト和文フォントを `fonts/` に取得済み（全OFL）。一覧と使い分けは `fonts.py --list` / [[DESIGN_SPEC]] §8。
**表紙インパクトは Dela Gothic One / Zen Kaku Gothic New Black が頭一つ抜ける**（既定Notoは細くサムネで弱い）。
エンジンは `<repo>/post/_brand.py` でフォントをハードコードしているので、1アプリの見出しだけ上げたいときは serif/heading パスを差し替える（既定挙動は不変。全体最適は段階的に）。

## 使われ方（活用ポイント）
- **sns-daily-pipeline**：日次生成（手順4企画・5生成）で本スキルの規範に従い、素材を全スライドに敷き、`qa.py`＋目視レビューを回す。
- **各アプリ sns-post**：手動で1本作るときも本スキルの [[DESIGN_SPEC]]/[[MATERIALS]] に従う。
- 4アプリ共通。`gen.py` は repo 非改変（tone の bg repo相対パス対応も gen.py 側で吸収済み）。
