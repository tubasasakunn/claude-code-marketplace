# LAYOUTS — レイアウト（配置・グリッド・ゾーン・階層）の正本

「**要素を画面のどこに・どう置くか**」の型と数値。2024–2026のグラフィック/エディトリアル/SNS運用リサーチ統合。
[[PATTERNS]] が「何を作るか（内容の型）」なら、ここは「**どう配置するか（視覚の骨格）**」。[[DESIGN_SPEC]]（原則）と重なる所は数値の正本としてこちらを参照。
雛形（`templates/standard.py`）はこのゾーン定数・階層に沿って作る。新しい配置型が要るなら variant/雛形を追加して育てる。

---

## 1. 基礎システム（骨格の決め方：グリッド→焦点→視線→余白→整列）

- **8pxグリッド**：全座標・余白・サイズを **8の倍数**にスナップ（複数枚シリーズの揺れを消す）。
- **6列グリッド**（縦長は2/3に割れて扱いやすい）：外側 `M=80px`、ガター `G=24px`。
- **三分割法**：縦1920→ y=640/1280、横1080→ x=360/720。**4交点が焦点**（被写体の目・キー要素・SWIPEを置く）。
- **黄金比 1.618**：より洗練・非対称が欲しい時は **62:38** 分割（三分割の33:67より片寄る）。要所のみ。
- **対称＝安定/格式・静的、非対称＝動的/モダン**。視覚的重み＝色(暖色は重い)・サイズ・テクスチャ・空間で取る。
- **視線**：Z型(要素少・CTA1つ＝カバー)／F型(テキスト多＝info)／中心(1メッセージ)。縦長は基本「上→下」のスクロール順。
- **余白**：マクロ(ブロック間 48–72px)＋ミクロ(行間・パディング)。水平:垂直マージン＝**1:2**。詰め込みは素人感No.1。**余白の数値・トークン・間延び対策は [[SPACING]] が正本**（8の倍数スケール／内側<外側／等間隔中央寄せ）。
- **整列**：1枚内は**左揃え or 中央揃えのどちらかに統一（混在禁止）**。テキスト多→左揃え、カバー/1メッセージ→中央。

## 2. 配置ゾーン定数（Pillow機械生成の基準・1080×1920）★2026-07-25 実測で全面改訂

> **旧値(TOP 160 / BOTTOM 340 / RIGHT 140)は出所不明の伝承で、実際より 80〜330px 小さかった。**
> 「安全」と判定していた領域が実機ではUIに隠れていた。実装正本は `scripts/qa.py: SAFE`。

**根拠（独立2ソースが一致）**

1. **TikTok はセーフゾーンを公式配布している** —— 散文ではなく DL 可能な **ZIP テンプレート**として。
   だからテキスト検索では見つからない。その公式アートワークをピクセル実測: `top=240 / bottom=660
   （キャプション1行で810+）/ right rail=180`。
2. **Meta 公式の 9:16 セーフゾーン（上14% / 下35% / 左右6%）** を px 換算すると `top=269 / bottom=672`。
   → 別プラットフォームの別文書が、両バンドとも**約4%以内で一致**。伝承ではなく実体。

⚠️ 出回っている **`130/483/140/44`** のセットは **AI-SEO の捏造**。再輸入しない
（Hootsuite/Sprout が他プラットフォームの数値は出しつつ TikTok だけ空欄なのが傍証）。

```
# セーフエリア（UIに食われる領域＝重要要素を置かない）@1080×1920
TOP_SAFE    = 270px   # 上UI。実測240 + 余裕
BOTTOM_SAFE = 810px   # 下UI(キャプション+操作)。実測660、キャプション1行で810+
RIGHT_RAIL  = 180px   # 右アクション列。※ y>=840 にしか存在しない（下記）
SIDE_MARGIN = 120px   # 左右の**作画余白**。※UIに食われる領域ではない（左側にUIは無い）
                      #   実装の既定は sp("edge")=88px。美観の判断なので 88〜120 の幅で可
→ 安全作画域: y[270 .. 1110] ＝ **フレームの44%しか使えない**
```

**★ 安全域は矩形ではなく L 字**

右のアクション列（いいね/コメント/シェア）は **y=840 から下にしか無い**。
つまり **y<840 は全幅使え、y>=840 で右180pxが死ぬ**。上部の見出しは右端まで伸ばしてよい。

```
 0 ┌──────────────┐
   │   上UI (270)      │ ← 触らない
270├──────────────┤
   │                    │
   │   全幅つかえる       │  ← 見出しは右端までOK
840├───────────┬──┤
   │           │右 │ ← 180px
1110├──────────┴──┤
   │   下UI (810)       │ ← 触らない。**CTAを置けない**
1920└──────────────┘
```

**★「CTAは親指の届く下中央へ」は TikTok では成立しない。** 下は丸ごとUIに食われる。
CTA は **中央帯（y 270–1110）に置くか、キャプション文へ逃がす**。この定石は
あらゆるソーシャルデザイン指南が繰り返しているが、TikTok に関しては単純に誤り。

```
# 縦3バンド（改訂後の配置骨格・安全域 y270–1110 を3分割）
上バンド(見出し)      : y 270–620   (約18%)  … フック/見出しを大きく
中バンド(主役ビジュアル): y 620–950   (約17%)  … 写真/実画面/数字
下バンド(補足/CTA)    : y 950–1110  (約8%)   … ここが実質の「下」。これ以下は使えない
```

**Lemon8 / Instagram（1080×1440・3:4）** はフィードが全画面でないためUI被りが軽い。
`top=130 / bottom=173 / left,right=96`。ただし**グリッド表示のクロップ**があるので外周は確保する。

- **Instagram の縦最大比は 3:4（1080×1440）**。4:5 でも 9:16 でもない。2025-01 にプロフィール
  グリッドも 3:4 になったため、**1080×1440 がフィードとグリッド両方でクロップゼロの唯一のキャンバス**。
- **Instagram の枚数上限はパスで違う**: アプリ経由 20枚 / **Graph API 経由は 10枚**。
  自動投稿パイプラインは **API 側の10枚に拘束される**。
- 写真上テキストは必ず**スクリム(下40%を黒α0→0.55)か全面オーバーレイ**で**コントラスト比4.5:1**（大文字3:1）確保。
  スクリムの不透明度は **Apple HIG が 35%、Material が 32%**（AOSPソースで検証済）＝この辺りが妥当。

## 3. 配置テンプレ型 — 表紙(cover)

縦の3バンドで考える。自分たちの cover variant 対応を併記（無いものは雛形追加候補＝§7）。

| 型 | 配置の要点 | 視線 | いつ効く | 対応 variant |
|---|---|---|---|---|
| 全面タイポ(文字支配) | 背景単色/薄、見出しを上〜中央に特大(ジャンプ率3–4) | 中央 | 断定・逆張り・メッセージ性 | `editorial`(bg無し) |
| 写真＋下帯キャプション | 全面写真＋下スクリム＋文字 | 写真→下文字 | 万能(実画面/被写体＋情報) | `editorial`/`quote`(bg有) |
| 写真＋中央大文字 | 写真を暗く/ぼかし＋中央に短い大文字 | 中央 | 引用・宣言・インパクト | `quote`/`versus` |
| 被写体片側＋反対に文字 | 写真内の余白(空・床)に文字、被写体は逆側 | 被写体→文字 | 人物・商品 | `editorial`(写真選定) |
| 上タイトル＋下に被写体見切れ | 上に見出し特大、端末/被写体を下端から12–22%見切れ | 上→下 | 実アプリ画面・操作 | `shot`(見切れ・実装済) |
| 巨大数字中央 | 数字を画面高30–40%で中央、上に小見出し下に補足 | 数字一点 | リスト/ランキング/統計 | `numeric`→`numeric-giant`(追加候補) |
| 斜め分割 | 対角線で2領域、勢い | 対角(Z強化) | Before/After・VS・躍動 | `split`/`versus`→`diagonal`(候補) |
| 雑誌風(大英字＋小見出し＋囲み) | 特大英字を上1/3、小コピー/囲みを周囲 | 大→小 | おしゃれ・特集・Lemon8 | `magazine`(追加候補) |
| 額装(太枠＋内側余白) | 周囲に均等マージンで額縁 | 内側集中 | 上品・統一・シリーズ | `frame_ticks`(既存装飾) |

**カバー定石**：太い**5〜8語/全角10〜14字**のフック見出し(スライド最大文字)＋パターン割込み(高コントラスト/表情/劇的図)＋好奇心トリガー(部分露出/数字/問い)。サムネで成立させる(中央〜上・高コントラスト・短文)。

## 4. 配置テンプレ型 — 中面（情報/実画面）

| 型 | 配置の要点 | いつ効く | 対応 |
|---|---|---|---|
| 上見出し＋下本文 | 重要度=上から下。見出しと本文は近接でグループ化 | 解説・手順 | `info`/`shot` |
| 左図右文(or逆) | 縦割り、図と文の高さ中心を揃える | 図と説明の対応 | （雛形追加候補） |
| 上下二分割 | 横割り、分割比はジャンプ率をつける | 風景/縦長被写体/対比 | `split` |
| カード3〜4分割グリッド | 格子配置、要素サイズに変化、余白均等 | 比較・○選・バリエーション | （追加候補） |
| 番号＋一言の縦並び | 左に番号バッジ(左端揃え)、右に一言。縦に反復 | リスト/チェックリスト(保存主力) | `info`(実装済) |
| 中央寄せ1メッセージ | 1文を中央に大きく、余白を大胆に | 結論・転換・強調 | `photo`/新規 |
| 写真全面＋テキストオーバーレイ | 写真背景＋帯/スクリム上に文字 | 共感・世界観 | `photo`(実装済) |

中面共通：**1スライド=1メッセージ**、主要素は**3ブロック以内**（見出し/主役/補足）、本文40〜80字・3行まで。

## 5. 階層とリズム（ジャンプ率・型スケール）

1080幅で読ませる前提のサイズ目安（Web値より大きめ）：

```
DISPLAY(数字/カバー) : 140–200px   ← フック・巨大数字
H1 見出し           :  72–104px
H2 サブ見出し       :  44–60px
BODY 本文           :  32–44px    ← 最小32px(=画面高2.5%)未満は書かない
CAPTION             :  24–28px
```

> **最小フォントサイズを公開しているプラットフォームは存在しない。** TikTok の公開文書一式に
> フォント・サイズ・可読性の記述はゼロで、「TikTok は N pt 以上を推奨」は**すべて捏造**。
> Apple の 11pt 最小は**アプリ内UI**の規定であってスクリーンショットには及ばず、
> WCAG 1.4.4 は画像内の文字を**明示的に適用除外**している。さらに **WCAG は CJK について
> サイズ指定を見送っている**ため、日本語では直接使えない。
> → **上の「本文32px＝画面高2.5%以上」は自前で決めた実務値**。それでよい。外部権威を引く必要はないし、
> 引ける権威も存在しない。**外部の数値を持ち出している記述を見たら疑うこと。**

**可読性で確かなこと**（読字速度の実験値）: **小文字は +26%、コンデンス書体は +11.2%** 読む時間が増える。
フィードの滞在は **1.7秒**（Facebook IQ・850以上の広告）で、ストアページの3〜6秒とは桁が違う。
→ **コンデンスの小文字は、スクロールで一瞬しか見られない面では最悪の選択**。
- **ジャンプ率**：表紙 **3.0〜4.0**、内ページ **2.0〜2.5**。中間域は1.25前後で詰め、ディスプレイ端で1.6前後に開く。黄金比1.618も指標。
- 優先度は **サイズ＞太さ＞色＞位置**。最大要素＝最重要。強調ワードは最大3つ。
- **繰り返し**：見出しフォント・アクセント色・マージン・バンド境界を全スライドで反復＝1つのコレクションに見せる。リズムは余白の間隔で作る。

## 6. テキストの置き方・写真との関係・一貫性

**テキスト**
- 縦位置：フックは上〜中央、**上に死に空間を広げない**。行間=フォントの1.5倍(大見出しは1.3〜1.4)。字間=本文5%、英字ラベルは広げ、大見出しは0〜詰め。
- 文字数：文字のみ表紙 ≤22字、写真メイン ≤15字。1行は大見出しで全角10〜14字。
- 近接：見出しと本文を近づけ1グループ、グループ間は離す。整列基準(左端/中心軸)を1本の透明線に吸着。
- **日本語の改行**：文節(助詞の前で切らない)で改行、固有名詞・商品名は行をまたがせない、行頭行末禁則(句読点・閉じ括弧)。単語の途中改行禁止。原稿に `\n` で改行位置を明示。

**写真/実画面 × 文字**
- **重ねない**のが基本：写真の余白側(空・床・単色)に文字。被写体・顔・主役UIの上に置かない。
- 重ねる時：①下スクリム(最汎用) ②半透明帯(α0.5–0.7・角丸・写真の形に沿わせる) ③縁取り＋薄影 ④不透明塗り30–50% ⑤背景ぼかし。
- 被写体の**視線/体の向き**が文字側を向く写真を選ぶ。視線方向・矢印・光の流れで次要素へ誘導。

**シリーズ一貫性**
- 見出しy位置・ノンブル(番号)・色帯・余白を**全スライド固定**。タイトル位置・端末位置を投稿間でも揃えるとフィードで統一感。番号バッジで進捗→完読、途中にSWIPEで「次がある」を提示。

## 7. 雛形の配置まわり 追加候補（優先度順・育てる）

**高**
1. **`numeric-giant`**（巨大数字中央）：数字を画面高30–40%・中央、上に小見出し/下に補足、ジャンプ率4.0+。統計/ランキング/リストに最強コスパ。
2. **`magazine`**（雑誌風カバー）：特大英字タイトルを上1/3、小コピー/囲みを周囲。Lemon8向け。
3. **配置ゾーンを比率定数化**：上テキスト域0–36%/下ビジュアル域33–100%（表紙）、見出し帯0–22%/本文22–78%/フッタ78–100%（中面）を共通定数に。

**中**
4. **align フラグの強制**：`info` 等で `align: left|center` を1つだけ許可、混在を生成時に弾く（素人感の最大要因）。番号バッジの左端xを全 info 共通定数に固定。
5. **写真の文字ゾーン自動回避**：`photo`/写真型 cover で「文字を置く側」を指定、反対側 or 下スクリム域のみにテキスト。重なれば自動スクリム。
6. **`diagonal`**（斜め分割）：Before/After・VS用に対角で2領域＋各中心にラベル（`split`/`versus`派生）。

**低（磨き）**
7. 光学的中央ずらし（中央寄せを既定2–3px左オフセット）。8. 黄金比ジャンプ率ヘルパー(見出し=本文×1.618)。9. 日本語改行ヘルパー(文節/固有名詞非分割/禁則)。10. 投稿単位の固定ヘッダ/フッタ・色帯テーマ辞書（コレクション感）。
