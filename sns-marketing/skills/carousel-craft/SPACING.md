# SPACING — 余白（ホワイトスペース）の正本

「**要素のまわり・あいだに、どれだけ・どう空けるか**」の正本。縦長カルーセル（TikTok 1080×1920 / Lemon8 1080×1440）を Pillow で機械生成する前提で、**座標計算に落とせる数値**だけを置く。
[[LAYOUTS]] が「要素を画面のどこに置くか（骨格）」なら、ここは「**そのあいだの空気をどう設計するか（余白）**」。余白は「余り」ではなく**能動的なデザイン要素**。詰め込み・不揃い・間延びは素人感の三大要因で、その大半は余白の設計ミス。
実装は `engine/brand.py` の **スペーシングシステム**（`SP_SCALE` / `sp()` / `snap()` / `stack_centered()`）＝この文書の数値が正本、コードがその実装。

> 大原則（これだけは外さない）
> 1. **離散スケールに乗せる**：余白は決まった段（8の倍数）の値しか使わない＝孤立余白とリズム不統一を構造的に潰す。
> 2. **内側の余白 < 外側の余白**：群の中は近く、群の外は遠く（近接でグループを作る）。
> 3. **左右マージンは対称**：`margin_left == margin_right`。非対称は意図がある時だけ。
> 4. **死に空間と意図的余白を分ける**：その空白が「分離・強調・視線誘導」のどれかを担うなら意図的、何も担わないなら間延び＝詰める。

---

## 1. 余白の種類（まず分けて考える）

- **マクロ余白**：主要ブロックどうしの大きな間（外周・島と島の間）。**読ませる/招き入れる**＝「macro-space makes text inviting」。
- **ミクロ余白**：要素内部の小さな間（行間・字間・アイコンとラベルの隙間・帯の内側パディング）。**読みやすくする**＝「micro-space makes it legible」。
- **アクティブ余白**：視線を導き・強調・間を作るために**意図して置く**余白（構図上の決定）。主役の四周に確保するクリアスペースなど。
- **パッシブ余白**：読みやすさのため自然に置く受動的な間（外周・行間）。
- **ネガティブスペース（地）**：被写体・文字（図）に対する「地」。**図と地は等価に設計**する（地は背景の余りではない）。

実装：余白を2系統の定数に分離して持つ＝`engine/brand.py: SP_TOKENS`（`edge/group/block/hd_body/pad/hero…`）。アクティブ余白は主役の `hero`(=64px) クリアスペースとして明示変数で持つ。

---

## 2. スペーシングスケール（最重要・全ての余白の土台）

**8の倍数**を基準スケールにする（4は密所だけの半ステップ）。8は2・4で割り切れ、複数枚シリーズの揺れを消し、縮小しても整合する。

```
SP_SCALE = (8, 16, 24, 32, 40, 48, 56, 64, 72, 80, 96, 112, 128, 160)   # 1080基準px
これ以外の余白は原則使わない。中途半端な 35/50/70px が孤立余白(trapped)とリズム崩れの元。
```

- 任意pxは `B.snap(v)` で最も近い段へ吸着させる（段差を2〜3種に収束）。
- **段差は1スライドにつき2〜3種まで**（例 16 / 32 / 64）。種類が増えるほど素人っぽくなる。

意味づけトークン（`B.sp("name", W)`・1080基準px）：

| トークン | px | 用途 |
|---|---|---|
| `edge` | 88 | 外周マージン（W×8.1%）。`margin()` と一致 |
| `edge_tight` | 72 | 詰めた外周（Lemon8 / 下帯） |
| `hd_body` | 16 | 見出し→直下本文（近接でグループ化） |
| `block` | 32 | 同一群のブロック間 |
| `group` | 64 | 別の視覚的島の間 |
| `section` | 96 | 大きな段（見出し島↔本文島） |
| `pad` | 32 | カード/パネル内側パディング |
| `pill_y/pill_x` | 16/24 | 帯・ピル内側（縦/横） |
| `hero` | 64 | 主役まわりの強制クリアスペース |

---

## 3. 外周マージン（エッジ余白）

- **左右 = W×6.7〜8.1%（72〜88px）**。既定は `edge`=88（=現行 `margin()=W×0.085`）。下帯・Lemon8は `edge_tight`=72。
- **左右は対称**（`margin_left == margin_right`）。背景写真の上でも文字・ロゴはこの外周を侵さない。
- 上下の作画余白はセーフゾーンと兼ねる（§7・[[LAYOUTS]] §2）。要素をエッジに貼り付けない＝最低 `edge_tight` は空ける。

---

## 4. 要素間マージン（マクロ）と近接

**内側 ≤ 外側** を不変則にする。見出しと本文を近づけて1グループ、グループ間は離す。これだけで囲み無しにグループが立つ（近接の法則）。

| 関係 | 段差 | トークン |
|---|---|---|
| 見出し → 直下本文 | 16px | `hd_body` |
| 同一群のブロック間（段落・カード間） | 24〜32px | `block` |
| 別の視覚的島の間 | 48〜64px | `group` |
| 見出し島 ↔ 本文島（大段） | 96px | `section` |

- **悪い例**：見出し→本文 40px、本文→次見出し 40px（段差が同じ＝群が分からない）。
- **良い例**：見出し→本文 16px、群→次の群 64px（段差4倍で群が一目で分かる）。

---

## 5. パディング（ミクロ・内側余白）

- **パネル/カード内側**：24〜32px（`pad`）。`pad < 16px` は窮屈＝素人感。
- **帯/ピル/ラベル**：縦 16px・横 24px（`pill_y/pill_x`）。テキストの上下左右を非対称にしない。
- **CTAボタン**：縦 20〜24px・横 32〜40px。
- **行間** ＝ フォントの **1.5倍**（本文）／大見出しは詰めて 1.2〜1.4倍。**字間** ＝ 本文 ≧0.12em（≈5%）、英字ラベルは広げ、大見出しは0〜わずかに詰め。段落間 ≧ フォント2倍。
  - Pillow: `line_h = round(font_px*1.5)`、`tracking = round(font_px*0.02)`。
- **アイコン⇔ラベル**の隙間は密所として 8px（半ステップ）まで許可。

---

## 6. 死に空間（間延び）と孤立余白の潰し方 ★現状の弱点

「**その余白は分離・強調・視線誘導のどれかを担うか？**」を問う。担わない空白＝死に空間（dead space／間延び）。

- **孤立余白（trapped/orphaned）**：要素間に残る中途半端な空き。事故っぽく、視線が途切れる。
  → 対策：§2スケール外の値を使わない＋`B.stack_centered()` で**等間隔リズム＋中央寄せ**にする（内部の孤立ギャップを上下の対称 breathing に変換）。
- **間延び（縦の死に空間）**：少数項目を帯いっぱいに引き伸ばすと、項目間に巨大な空きができる。
  → 対策：**等高ブロックを一定 gap で詰めて、塊ごと中央寄せ**。gap は `block`(32)〜`section`(96) にクランプし、引き伸ばしの上限を作る。余りは上下に均等＝対称な breathing room（＝意図的余白）に変える。
  → 実装の正解形：`slide_info`（箇条書き）・`slide_cta`（検索バー→アイコン→DLの3要素）はこの方式。**3要素以下を縦に置くときは必ず「等間隔の塊を中央寄せ」**（バラ撒かない）。
- **qaで検知**：`scripts/qa.py` の `DEAD-BAND` フラグ。info/cta の内部最長空白が **H の20%超**で警告（実素材スライドは対象外）。出たら詰める。
- 逆に**詰めすぎ**も禁止：群の内外で段差を必ずつける（§4）。

---

## 7. 縦長SNS特有（セーフゾーンと「上の死に空間」の両立）

- セーフゾーンは [[LAYOUTS]] §2 / [[DESIGN_SPEC]] §1。**TikTok下480px・右140px、Lemon8下173px**には主役・CTA・ロゴを置かない（その帯は地＝余白として残す）。
- **「上に死に空間を作らない」と「上UI帯（〜160px）を避ける」の両立点**：上端ピッタリではなく、**上UI帯のすぐ下（y≈180〜620）にフックを置く**。下のUI帯は余白として残す。
  - 例外：cover の「写真＋下帯キャプション」型は、上を写真の breathing room として使い、フックを下スクリム上に置く（写真が地を埋めるので死に空間にならない）。文字だけ表紙は上〜中央に。
- **サムネ縮小耐性**：1/4縮小でも潰れないよう、要素間の最小段差は**実寸32px以上**（`block`）。これ未満の隙間は縮小で消える。

---

## 8. 一貫性（シリーズで余白を固定）

- 全スライドで**外周マージン・左基準線・段差スケール・行間倍率を固定**＝コレクション感。
- 余白は**1つの定数モジュール（`SP_TOKENS`）から全テンプレが参照**し、スライド個別に直書きしない。これでシリーズの余白リズムが自動で揃う。
- 左端は**2〜3px精度で完全に揃える**（全行が同じ左基準線 `x=M` を共有）。左揃え/中央揃えは1枚内で混在させない（[[LAYOUTS]] §1）。

---

## 9. 目視チェック（余白）

- [ ] 左右マージンが対称か（片側だけ詰まっていないか）
- [ ] 見出しと本文が近接し、群と群が離れているか（段差に4倍程度の差があるか）
- [ ] 項目間の隙間が**均等**か（一箇所だけ広い孤立余白がないか）
- [ ] 縦に**間延び**した死に空間がないか（少数項目を引き伸ばしていないか＝塊で中央寄せか）
- [ ] パネル/帯の内側パディングが窮屈でないか（≥24px）
- [ ] 上UI帯直下にフックがあり、上に無駄な死に空間がないか
- [ ] 余白の段差が2〜3種に収まっているか（中途半端な値が混ざっていないか）

## 10. 実装ヘルパー（`engine/brand.py`）

```python
B.snap(v)                       # 任意px → 最も近いスケール値
B.sp("group", W)                # 意味づけトークンを幅Wへスケール
B.stack_centered(top, bot, n, row_h, gap_min, gap_max)
#   n個の等高ブロックを帯に「等間隔リズム＋中央寄せ」で配置し各先頭yを返す。
#   gap は (band-n*row_h)/(n-1) を [gap_min,gap_max] にクランプ＝間延びを上限で止める。
#   → slide_info / slide_cta が使用（縦の死に空間・リズム崩れの正解形）。
```

## 11. 質感・画質（grain は写真背景にだけ）★画質荒れの主因

余白だけでなく**面の質感**も「荒い／安い」印象を左右する。最大の地雷が **grain（フィルムノイズ）の誤用**。

- **grain はフラット面に載せない**：ベタ塗り・グラデ・ベクター文字の上にノイズを重ねると、**JPEG圧縮ノイズ状の『画質荒れ』**に見える（特に旧実装の 2x2 NEAREST ブロックは顕著）。info / cta / クリーン背景の shot には**grain を一切載せない**。
- **grain は写真背景にだけ薄く**：実写・footage の上だけ、`amount≈7`・full解像度の細かいグレインで**映画的な質感**として足す（`coarse=False` 既定）。写真は元々テクスチャがあるのでノイズが馴染む。
- 実装：`B.grain(canvas, amount=0)` で無効。`engine/brand.py` の `grain()` は既定 full解像度・微細。`templates/standard.py` は **`shot` の `bgp` がある時だけ** grain を呼び、`info/cta` では呼ばない。
- 関連：文字は**アンチエイリアスの効いたシャープなエッジ**を保つ（ノイズ・過度なシャドウ・袋文字の重ねがけでエッジを潰さない）。スクリム/シャドウは§5・[[DESIGN_SPEC]]§5の範囲で。

> 目視チェック（画質）：フラット面に**ザラつき／砂目**が出ていないか。文字エッジが**シャープ**か。写真の grain が**細かい film** で、ブロック状の粗いノイズになっていないか。→ raw PNG を等倍〜2倍で1枚確認する。
