# PATTERNS — 投稿/スライドの型カタログ（雛形から選んで毎回新しく組む）

縦長カルーセル（TikTokフォトモード/Lemon8）で伸びる**型のライブラリ**。2024–2026・日本市場のリサーチ統合（出典は各節末）。
[[SKILL]] の企画で**毎回ここから1つアーキタイプ＋1つフックを選ぶ**（ワンパターン化を避ける）。新しく効く型が分かったら**追記して育てる**。
自分たちのスライド型＝`cover`(6 variant: editorial/question/quote/split/versus/numeric)・`photo`・`shot`(実画面・見切れ)・`info`(番号リスト)・`cta`(検索誘導)。

> 共通原則：**枚数はU字。谷は4〜5枚、6〜9枚が最強**（下記）／**1スライド=1メッセージ**／
> **1スライドの強調は1点だけ**（メタ分析で複合キューは効果が反転）／保存・完読・滞在・送信が最重要シグナル。

### 枚数 ★2026-07-25 実測で改訂（旧記述「4〜7枚が最弱」は6〜7枚を過小評価していた）

**3つの独立ソースが同じU字を示した**。枚数に関する主張のうち、再現性が確認できたのはこれだけ。

| ソース | 標本 | 示している形 |
|---|---|---|
| Lemon8 実投稿クロール（自前・一次） | 1,087投稿 | **4–5枚が谷**（いいね中央値124）、6–7枚で最高（594）、8–9枚(530)、10枚+(482) |
| **TikTok 公式** Image Ads Playbook | 非公開 | 「**3枚 または 7–9枚**を使え。この枚数がCTR・CVRが良いと分かっている」＝4–6枚に谷 |
| Socialinsider 2020 | 2,200万投稿 | エンゲージメント率は**3枚目以降で落ち、8枚目以降で再上昇** |

→ **3枚で振り切るか、6〜9枚まで積む。5枚前後は最も避けるべき枚数。**
上位60件の平均7.4枚 vs 下位60件5.7枚で、枚数は伸びと正相関。`qa.py` が4〜5枚を警告する。

⚠️ 出回っている「5-8枚が最適」「12枚以上で40%離脱」は**すべて出典なし**（AI-SEOスパム発）。
枚数上限は **Lemon8 10枚 / Instagram 20枚(アプリ)・10枚(Graph API) / TikTok 35枚**。
Lemon8 で10枚が多いのは**上限に張り付いているだけ**で、伸びているからではない。

### 三部構成は「絶対」ではない

「表紙→本文→CTA」はノウハウ記事が一様に説くが、**Lemon8 実測では最終スライドにCTAを置くのは32%だけ**。
7割は情報を出し切って終わる。CTAスライドは目的（DL誘導）があるから置くのであって、
様式として必須ではない。→ CTAの実務は §3「CTA(最終)」。

### 型の優先順位（アプリ宣伝では実測がある）

AppsFlyer 2025 State of Creative Optimization（**110万クリエイティブ / 広告費24億ドル / 1,300アプリ**）:

- **ソーシャル系アプリでは、チュートリアル型UGC が「お客様の声」型を上回る —— IPM +45% / 7日リテンション +17%**
- 金融アプリの UGC チュートリアル: リテンション +37%
- 「失敗→成功」ナラティブ（ハイパーカジュアル）: IPM +78% なのに予算は40%少ない＝過小投資

→ **[アプリ]デモ / ハウツー・ステップ / 成果物ショーケース を優先し、社会的証明（レビュー引用）は後回し。**
※ これは動画広告のデータでカルーセルではないが、型の優劣としては本調査で最大規模の実測。

## 1b. 実物から起こした中面テンプレ（Lemon8 上位投稿を1枚ずつ分解・2026-07-25）

いいね上位のアプリ紹介デッキを実際に目視分解して起こした、**そのまま組める**4つの型。
A/B は複数アプリ紹介、**C/D が単一アプリ＝自分たちの立場**。

### A型：スクショ全面ブリード ＋ 白カード浮かせ（複数アプリ）
実例「【必見】激推し神アプリ」6,899いいね・9枚
```
┌──────────────────┐
│ (01) ● 被らない激安通販  │ ← 上部白帯。黄丸の手書き風番号＋見出し
├──────────────────┤
│ ┌── アプリ実スクショ全幅 ──┐ │
│ │ ┌────────────┐ │ │
│ │ │[ロゴ] SHEIN(シーイン)│ │ │ ← 白角丸カード＝アプリ名プレート
│ │ └────────────┘ │ │
│ │ ┌────────────┐ │ │
│ │ │ 説明文 5〜7行        │ │ │ ← 白の説明カード
│ │ └────────────┘ │ │
│ └──────────────┘ │
│              [アバター]  │ ← 右下に固定＝署名
└──────────────────┘
```
- 番号バッジ・見出し・アバターの位置を**全スライドで完全固定**＝コレクション感（素人との最大の差）
- 終盤に**まとめスライド**（番号リストで全再掲）→ 最終スライドで他投稿サムネ3枚へ回遊

### B型：無地地 ＋ アイコン主役 ＋ 定型スペック行（ランキング）
実例「【2021版】有能アプリランキング6位〜1位」3,974いいね・10枚
```
┌──────────────────┐
│ 6      reminDo          │ ← 巨大順位数字＋アプリ名(英字・字間広)＋罫線
│      [大きなアイコン]      │ ← **スクショではなくアイコン**
│  使用頻度 ｜ 毎日          │ ← 投稿独自の定型フィールドを全スライド反復
│  暗記度   ｜ ★★★★★      │
│  ───────────────      │
│  一言キャッチ（下線付き）      │
│  本文（重要語に黄マーカー）    │
└──────────────────┘
```
- 実写の両手が下からアイコンを捧げ持つ構図を10枚すべてで反復＝強烈なシリーズ性
- **様式が信頼感を作る**。定型フィールドは中身より「揃っていること」が効く

### ★C型：実機の斜め写真 ＋ 機能ラベル（1機能=1スライド）── 単一アプリの本命
実例「鬼集中するとき専用アプリ」2,210いいね・10枚
```
┌──────────────────┐
│      ▓▓ 時間帯ブロック ▓▓  │ ← 角丸ラベルに機能名。全スライド同位置
│   ╱────────╲          │
│  │ 実機を斜め45度で │        │ ← デバイスモックではなく**実機の実写**
│  │  実写（ケース付） │        │   全スライドで同じ角度・同じ位置
│   ╲────────╱          │
│  説明文3〜4行             │
│  重要語に黄色い蛍光マーカー     │ ← 手書き風フォントで距離を縮める
└──────────────────┘
```
構成: cover → **photo(共感=悩みの提示)** → shot(アプリ名の発表) → shot(機能)×6 → cta(自己紹介＋保存)

### ★D型：説明は2枚だけ、残りは全部「成果物」── 出力が映えるアプリの本命
実例「【カメラアプリ】激おすすめ old Roll」1,647いいね・7枚
```
[1] ホーム画面スクショ ＋ **手描き風の丸で該当アイコンを囲む**
    ＋ 青い蛍光帯に白文字「ほんとは教えたくないイチオシアプリ」
[2] アプリ内の設定画面。丸囲みで1点だけ指す  ← **説明はここで終わり**
[3-7] そのアプリで撮った作例写真だけ。**文字はゼロ**
```
- 作り込んだデザインではなく **iOS のマークアップでラクガキした見た目**
- 「友達が教えてくれた」質感が効いている。**洗練させると逆に弱くなりうる型**
- 紙面・画像・動画を生成するアプリなら、**成果物を並べるだけで成立する**

> **共通して効いている構造**: ①部品の位置を全スライドで固定 ②1スライド1メッセージ
> ③終盤にまとめ（保存の理由）④最終スライドで回遊 or DL導線。
> **カバーにも中面にも「実スクショ」は意外と出てこない** —— 複数アプリ紹介ではアイコンが主役。
> 散らかりを避けるため。**単一アプリはここで逆張りでき、スクショを主役にできる**（1投稿=1アプリだから）。

## 2. フックの型（1枚目）＝cover variant とコピーに対応

1枚目はサムネ兼フック。50ms で止め、好奇心ギャップで次スワイプを作る。コピーは**上段=フック(感情・抽象)＋下段=ベース(具体・数字)の2段組**、ひらがな7割。

| フック | テンプレ | 使う cover variant |
|---|---|---|
| 疑問形 | 「〇〇って実際どう？」「〇〇できてる？」 | question |
| 逆張り/否定 | 「〇〇はもうやめて」「〇〇は逆効果」 | editorial(断定) |
| ターゲット指名 | 「〇〇で悩む人だけ見て」「20代メンズ必見」 | editorial / question |
| 数字 | 「〇〇する7つのコツ」「3選」 | numeric |
| カリオシティ/オープンループ | 「これだけで変わる」「最後まで見て」 | editorial / question(answer伏せ) |
| 告白/失敗談 | 「〇〇で大失敗した話」 | quote |
| Before/After宣言 | 「〇kg痩せた方法」「こうなりました」 | split |
| 断定/常識破壊 | 「〇〇は不要」「実は逆」 | editorial |
| 共感(あるある) | 「〇〇しがちじゃない？」 | quote |
| 緊急/限定 | 「今だけ」「〇月までに」 | editorial |
| 結果先出し | 「30日で〇〇」「1週間で変わった」 | numeric / editorial |
| 比較 | 「Aと B どっち派？」「NG vs OK」 | versus |
| 衝撃の統計 | 「87%が失敗」「5人に1人」 | numeric |
| 約束 | 「これ見れば〇〇できる」「保存して」 | editorial |
| チャレンジ/挑発 | 「スライド3まで見れる人少ない」 | editorial |
| 【保存版】ラベル(Lemon8) | 「【保存版】〇〇まとめ」 | editorial / numeric |

注意：オープンループ・断定・統計・約束は**本文で必ず回収**（しないと信頼を失う）。表紙でオチを言わない。

> ⚠️ **ただし「後ろの枚で回収」は法令上は不十分。** 消費者庁の打消し表示報告書（平成30年5月16日）は
> 強調表示が「無条件・無制約」に適用されると読まれるとした上で、打消し表示を **「配置箇所が強調表示から
> 離れている場合」に無効**としている。**カルーセルの「1枚目で断定→9枚目で注釈」はこれに該当する。**
> 条件や例外がある主張は、**同じスライドに同程度の視認性で**併記する。→ §5

### フック文言の実測（Lemon8 アプリ紹介306件・2026-07-25）

上位60件 vs 下位60件で使用数を比較した。**効いているのは実質「数字＋〇選」だけ**。

| 要素 | 出現率 | 上位60 | 下位60 | 判定 |
|---|---|---|---|---|
| **「〇選」** | 25% | **23** | 4 | ◎ 唯一の強い正相関 |
| 「神アプリ」 | 9% | 7 | 4 | ○ 弱い正相関 |
| 【】括弧 | 22% | 15 | 14 | — 差なし |
| 「無料」 | 11% | 8 | 8 | — 差なし |
| **絵文字** | 81% | 20 | **29** | ✗ **逆相関の気配** |

- **「〇選」の数字は 9 / 7 / 5 / 6 に集中**（9選と7選が各15件で最多）。10以上は急減。1項目1スライド＋表紙＋まとめ＝6〜9枚と噛み合う。
- **絵文字は盛っても効かない。** 出現率81%と定番化しているが下位のほうが多用。作法として広まっているだけ。
- ⚠️ **「〇選」が失敗する条件**: 情報が薄い／順番に意味がない／**結局どれが良いか分からない**。
  **並べるだけでは不足で、順位か「推し」を明示する。**
- **斜線枕詞 `＼〜／`** はタイトル文字列では3%だが**画像内の文字としては頻出**。
  ＝タイトルに書く部品ではなく、**カバー画像に描く部品**（「＼この夏はじめたい／」「＼コレ知ってる？／」）。

### 2枚目を、単体で表紙として成立させる

- **2枚目が最大の離脱点**（日本の運用データ）。
- かつ Instagram は「エンゲージしなかったフォロワーに**別のスライドを表紙にして再配信**する」（Mosseri）。
  → **2枚目が表紙になりうる**。1枚目の続き前提で作らず、単体で意味が通るようにする。
- ⚠️ なお **スワイプ率は測定可能な指標として存在しない**（Metaが公開していない）。
  「次スライドを見切れさせる」手法の効果は**原理的に誰も検証できない**ので、推測として扱う。

## 3. スライド単位のレイアウト型

### 表紙(cover)
全面文字(タイポ)／写真の上に帯／被写体＋余白に文字／巨大数字／Before-After二分割／VS対称／引用符／雑誌風タイトル／パノラマ見切れ。
**未完成の表紙**（切れた図/部分チェック/ぼかし結果/番号カウントダウン）が好奇心ギャップの共通手法。→ 既存 variant でカバー。雑誌風/巨大数字は将来追加候補(§6)。

### 実アプリ画面(shot)
フルブリード見切れ／デバイス枠／角度付き／手持ち／**ズーム・ディテール抜き(コールアウト矢印・強調は1点)**／複数端末／操作フロー連続／スポットライト(注目UIだけ明るく周囲ディム)。
- **先頭3枚が最重要**・1枚1訴求・装飾の盛りすぎ厳禁（強調は1点＝One nudge）。枠を使うなら**最新機種**のみ。framed/unframed は**カテゴリ依存→A/B**。
- 自分たちの `shot` は「見出し特大＋端末を下端から見切れ」が基準（[[DESIGN_SPEC]] §10）。コールアウト/スポットライトは追加候補(§6)。

**★「強調は1点」は経験則ではなく、メタ分析で確立した原則**（2026-07-25 追記）

| 知見 | 数値 | 標本 |
|---|---|---|
| ハイライトは注目させる（静的/動的） | 領域検出 **+55.2% / +62.2%**、注視時間ほぼ2倍 | HCEye, ACM ETRA 2024（査読付き・n=27） |
| **ただしハイライトは他の全てへの注意を抑制する** | 周辺への注目が測定可能なほど低下 | 同上 |
| **キューを重ねると効果が反転する** | 視覚キュー g=0.261 / 社会的キュー g=0.634 / **複合キュー g=−0.635** | Cueing メタ分析（40研究・N=5,049） |

→ 矢印・丸囲み・マーカー・スポットライトを**同じスライドで併用すると全体が壊れる**（弱くなるのではなく反転）。
**1スライドの強調は必ず1点に絞る。**
→ スクショ上のオーバーレイ・タップ表示は **App Store Review Guideline 2.3.3** が権威で、
「アニメーションのタッチポイント」を**明示的に許可**している。規約上の心配は要らない。

**ラクガキ注釈（作り込まない選択肢）** ── D型で実証されている型
手描き風のオレンジ/赤の丸囲み・iOS マークアップ風の蛍光帯。**作り込んだデザインより効く場面がある**
（「友達が教えてくれた」質感）。ブランドの統一感を捨てる代わりに生っぽさを取る。ジャンルとアカウントの
性格に依存するので、**エディトリアル路線と混ぜない**（どちらかに振り切る）。

### 情報/リスト(info)＝保存される主力
番号リスト／チェックリスト／比較表／ステップ(矢印)／アイコン+一言／見出し+箇条書き／カード分割／タイムライン。
**1枚1アイデア・40〜80字・本文3行まで・行間1.5〜2・余白10%以上**。抽象論は保存されない＝具体性必須。

### 社会的証明・信頼
レビュー引用カード(★行は本文直上・引用符・アバター+名前)／実績バッジ(累計DL/ランキング/受賞)／利用者の声／Before-Afterの実例。**実スクショで作り込み感を消す**。→ §5の法令ガード必読。

### 数字/統計/引用
巨大数字＋一言（数字を頂点・アクセント1色・大量の余白で視線直行）／出典付き統計（小さく必ず出典）／引用符＋セリフ。詰め込まない方が authoritative。

### CTA(最終)
保存うながし（矢印を保存ボタン近く・「次に〇〇する時のために保存」）／フォローうながし（発信価値とセット）／**検索窓プロンプト（〇〇で検索）**／**アプリDL（アイコン大＋名前＋App Storeで検索）**／クーポン。
- 自分たちの `cta` は**アイコン大＋アプリ名大＋検索窓＋「App Storeで検索」**（プロフィール導線は使わない・装飾は削る）＝[[DESIGN_NOTES]]。
- **なぜ検索誘導か（正確な理由・2026-07-25 裏取り）**：3プラットフォームとも**投稿内にクリック可能なリンクを置けない**
  （キャプションもコメントも不可）。唯一スケールする導線は「プロフィール → bioリンク」だが、
  **TikTok は bio リンクに 1,000フォロワー以上（or Verified Business Account）が必要**。
  → **未到達の間は検索誘導が実質唯一の選択肢**。判断は正しかった。
- ⚠️ **成立条件**: Apple は検索順位の要因に**ダウンロード数**を挙げており指名検索は効く。
  ただし前提として**その名前で検索して1位に出ること**。CTAに使う前に実機のApp Storeで必ず確認する。
  取れていなければ穴の開いたバケツ。
- ⚠️ **「保存してね」は裸で書かない**（`qa.py` が弾く）。Meta は明示的なエンゲージメント要求を
  **降格対象（engagement bait）**と定義。禁止ではなく条件付きなので、**「保存する理由」とセットにする**
  ──「保存してね」✗ →「**次に書けない日のために保存**」○。
  実測でも、貼るのをやめて「あとで見返したい感」を作った事例で**保存率 8%→18%**。
- **CTAは下端に置かない**（TikTok）。下810pxはUIに食われる。中央帯かキャプション文へ。→ [[LAYOUTS]] §2
- **最終スライドの前に「まとめ」を置く**のが実物の定石。保存を促すのではなく**保存に値する中身**を置く。
- **bioリンクは App Store 直リンク1本**。TikTok 公式が「アプリ内ブラウザは外部リンクチェーンを制限する」
  「直接リンクを推奨」と明記＝**Linktree等のハブは劣化する**。
- ⚠️ **TikTok は投稿時に「コンテンツ開示設定 → Your brand」を必ずON**。自社アプリ宣伝は商用コンテンツで、
  **開示しないと「おすすめ(FYF)」不適格**。しかも**開示してもリーチは落ちないと公式明言**＝無料のリスク削減。

### 装飾・モチーフ（素人っぽくしない）
余計なディテールを削る／**1スライド1モチーフ**／ブランド配色2〜3色を機能固定（背景1・見出し1・アクセント1）／同一書体・同一見出し位置・同一番号位置で「一貫したコレクション」に。途中の off-brand 色は低品質シグナル。

**★打消し表示（カルーセル構造そのものへの直撃・2026-07-25 追記）**

**景表法（社会的証明・効果・No.1で特に）**

### 実装済み（★2026-07-27 に6種を追加）

| 型 | 何をする型か | 効く場面 |
|---|---|---|
| `showcase` | 成果物を全面ブリードで見せるだけ（文字ゼロを許容） | 出力が視覚的に映えるアプリ（D型の中核） |
| `feature` | 実機＋**角丸ラベルの機能名を全スライド同位置**＋説明 | 多機能を1つずつ売る（C型の中核） |
| ★`panorama` | **N枚を貫く1枚の絵**を作り、担当区間だけ切り出す | 横スワイプでしか成立しない表現。絵が次へ続くこと自体がスワイプの動機 |
| ★`scrap` | 白フチのプリントを傾けて重ね、手描きの丸/蛍光帯を1つ | 手仕事の質感。**エディトリアルと混ぜない** |
| ★`grid` | 2列のカード格子（1セル＝ラベル1語＋本文1行） | 比較・○選・機能の一望 |
| ★`callout` | 実画面の**1点だけ**を丸で囲み周囲を落とす | 操作の手順（spot を1つしか受け取らない実装） |
| ★`giant`(cover) | 数字を画面高22%で置き、言葉を脇役に落とす | 統計・実績・「1日◯秒」 |
| ★`magazine`(cover) | 柱（英字ロゴ＋号数）→太罫→写真→キャッチ→英字 | 誌面の格を借りる。Lemon8 向け |
| ★`rank` | 巨大順位＋対象＋実画面を全スライド同位置で反復 | ランキング（1位は最後） |
| ★`table` | 2列の比較表（強調する側だけ地を敷く） | 比較・NG vs OK・思ってた/実際 |
| ★`bleed` | 実画面を**枠なしで全面ブリード**＋白カードを浮かせる | 実物A型。スクショを主役にする |
| ★`spec` | アイコン主役＋定型スペック行（3行を全枚数で反復） | 実物B型。**揃っていること**が効く |
| ★`steps` | 番号バッジを線で連結した縦のステップ図 | 手順（3〜4手に必ず収める） |
| ★`stats` | 実数を2〜3個並べる | proof。仕様から言い切れる数だけ |
| ★`recap` | 番号リストで全再掲（最終スライドの**前**） | 保存の理由を一望させる |

**panorama の作り方**：全体キャンバス（W×N 幅）に地・軸・コマを描いてから `crop`。**コマは境界の上に置く**
と、どのスライドにも「隣の続き」が半分だけ写る。ブランドが時間帯トークンを持つなら、それを横グラデにすると
**ブランドのトークンがそのまま時間の経過**になる（hioto で実施）。
⚠️ 全スライドで `stops`/`frames` を同じ内容にすること（1枚の絵を切り出すため）。

### アプリ紹介ジャンルの所見（2026-07-27 追加調査）

- **タイトルの3本柱は「〇選」「ランキング」「比較」**。Lemon8 のアプリ紹介は
  「【2025】入れてよかった神アプリ10選」のように **〇選＋年号＋一人称**が定番で、
  関連検索も「ランキング」「15選」「比較」に寄る。→ `rank` / `table` / `spec`。
- **いいねより保存が伸びる**（実物で いいね248 / 保存202）。実用情報として持ち帰られるジャンルなので、
  **まとめを最終スライドの手前に置く**のが効く。→ `recap`。
- **作り込んだ図より実物のスクリーンショット**。「デザインされた引用グラフィックより、
  実際のスクショのほうが本物らしく見える」。端末モックの枠すら外す型＝`bleed`。
- **実数はスクロールを止める**。ただし出せるのは**仕様から言い切れる数**だけ（DL数・No.1・実績は §5 の対象）。→ `stats`。
- **運用テンプレは3系統（リスト／ステップ／比較）でほぼ賄える**——実務記事が共通して挙げる整理。
  この3つに対応する型（`rank` / `steps` / `table`）が揃ったので、次からは中身の差し替えで組める。
