# image-gen-techniques — Python画像生成の汎用テクニック集

## 概要

Claude Code が Pillow スクリプトで画像を「生成 → Read で目視 → 修正」するループを、
速く・高品質に回すための技法リファレンス。2つの軸で構成する:

- [PILLOW.md](PILLOW.md) … 描画そのものの品質（タイポグラフィ / AA / エフェクト / SVG / 性能）
- [REVIEW-LOOP.md](REVIEW-LOOP.md) … レビューの精度（ビジョンの限界と対策 / 機械QA / ワークフロー）

**境界**: SNSカルーセルのデザイン規範（型・レイアウト・確定指摘）は `carousel-craft` が正本。
ここには「どのアプリ・どの媒体でも通用する技法」だけを置く。二重持ちしない。

## クイックリファレンス（最重要10項目）

| # | 技法 | 一言 |
|---|------|------|
| 1 | スーパーサンプリング | ImageDraw の塗りはAAされない。4xで描いて `LANCZOS` 縮小が定石 |
| 2 | anchor 指定 | `draw.text(xy, s, anchor="mm")` で座標計算なしの中央揃え |
| 3 | 縁取りは stroke_width + stroke_fill | 片方だけ指定しない（stroke_fill 省略で fill 色になり無意味） |
| 4 | 行送りは getmetrics | 描画文字列の高さ積み上げは行間が不揃いになる。ascent/descent 基準で |
| 5 | 自動折返しは getlength 実測 | textwrap は日本語で不正確。1文字ずつ幅を実測して折る |
| 6 | 絵文字は embedded_color=True | Pillow 8.0+。カラー絵文字フォント未ロードだと豆腐になる |
| 7 | 文字グラデはマスク合成 | L モードで文字を描き `paste(grad, mask=text_mask)` |
| 8 | scrim で可読性 | 写真上の文字は下端40%黒→透明の縦グラデを敷く |
| 9 | ピクセルループ禁止 | putpixel/getpixel は使わない。numpy / ImageChops / point() に寄せる |
| 10 | 目視と機械の役割分担 | 質的判断=Read目視、量的判断(コントラスト比/px越境)=Python計算 |

## レビューの3原則（詳細は REVIEW-LOOP.md）

1. **ビジョンの解像度上限を意識する**: Read で渡る画像は長辺 ~1568px に自動縮小される。
   1080×1920 のフル画像やコンタクトシートでは小さい文字（縮小後 ~12px 未満相当）は読めない
   → 細部は該当領域の**拡大クロップを別途 Read** する。
2. **数値で白黒つくものは機械チェック**: WCAGコントラスト比・セーフゾーン侵犯・bbox はみ出しは
   Python で決定的に計算する（Claude の空間推論・座標出力は公式に「近似的」とされる）。
3. **自己採点は甘くなる**: 生成した本人セッションのレビューは trust-then-verify gap がある。
   重要な成果物は別サブエージェント（フレッシュコンテキスト）に基準だけ渡して敵対的レビューさせる。

## このワークスペースでの使いどころ

- carousel-craft / promo-video のエンジン (`engine/brand.py` 等) を改善するとき
- 新しい描画プリミティブ（テキスト/エフェクト/合成）を書くとき
- QAスクリプトに機械チェックを追加するとき
- 生成画像のレビュー手順を設計するとき

## 終了条件（このスキルを参照した作業のチェック）

- [ ] 新規描画コードに AA 対策（SS か aggdraw）を適用したか
- [ ] テキストは折返し/はみ出しの扱いを決めたか（自動折返し or bbox 検証）
- [ ] 生成画像のレビューで細部は拡大クロップを使ったか
- [ ] 数値化できる品質基準は機械チェックに落としたか
