# 踏んだ罠

実装中に実際に壊れたものだけを書く。**どれも一度は踏む**ので、作り始める前に目を通すとよい。

---

## 端末モックの四隅検出

画面の四隅さえ取れれば射影変換で流し込めるが、その四隅を取るところで 3 回壊れた。

### 辺を角度順に並べると、対辺どうしが隣り合う

長方形の 4 辺は 2 組の平行辺なので、**角度でソートすると対辺が隣接する**。
その 2 直線の交点はほぼ無限遠で、座標が `-120518` のような値になる。

→ **凸包上の順序**（空間的に隣り合う順）で並べてから交点を取る。

### 1px の揺れで、まっすぐな辺が複数に割れる

書き出しのアンチエイリアスで輪郭が 1px 揺れる（`x=291` と `x=292` を行き来する）。
凸包は厳密なので、直線 1 辺が短い辺 3 本に分断される。すると「長い順に 4 本」で対辺が混ざる。

→ 連続する辺を**向きでまとめて**から選ぶ。角丸の弧も 1 つの塊にまとまるが、
そちらは直線に乗らないので**残差で弾ける**。残った塊に最小二乗で直線を当てる。

### 寝かせたモックで画面の縦横が入れ替わる

「画像座標で左上の点から時計回り」に並べると、端末が寝ているモックでは
画像上の左上が画面の左上とは限らない。スクリーンショットの幅と高さが入れ替わり、
**中身が 90 度倒れて入る**。

→ 画面は必ず縦長なので、**短辺が幅に来るまで巡回**させる。残る 180 度の曖昧さは
**ノッチ**（画面の中でマスクが抜けている穴）が上辺の側に来る向きで決める。

## 射影のずれ

### 端末の縁から背景が透ける

四隅にぴったり合わせると、丸め誤差 1px 分だけ画面の縁から地の色が覗く
（オレンジの背景に細い輪郭線が出た）。

→ 四隅を**中心から 0.6% 外へ広げる**。はみ出した分はフレームのベゼルが隠すので、
広げる側に倒すのが安全。

### 端末の四隅に白い三角が出る

スクリーンショットは矩形なので、モックの角丸からはみ出す。背景が明るい画面
（カレンダーなど）だと、そこが白い三角として覗く。

→ `.mock-shot` に**実機と同じだけの角丸**を入れる。縦横比 1:2.17 なので水平/垂直を
別指定する（`border-radius: 14% / 6.4%`）。

### プレビューの zoom で変形が二重に縮む

`getBoundingClientRect()` は zoom 後の実寸を返すため、`?preview=1` のときだけ
変形が二重に縮んで端末が小さくなる。

→ **`offsetWidth` / `offsetHeight`** を使う。zoom の影響を受けない CSS px が取れる。

## 配置

### 回転させると 2 台が近づく

`rotate` を掛けると見かけの幅が広がるので、座標上は 180px 空けたつもりでも
実際は 78px しか空かない。矢印を通す隙間が消える。

→ 回転後のバウンディングボックスで考える。幅は
`w·cos θ + h·sin θ`、高さは `w·sin θ + h·cos θ` に広がる。

### つなぎで片方にベゼルしか映らない

「またぎキャンバスの中央に置けば半分ずつ入る」と思うと外す。合わせるのは
**モック画像の中心ではなく画面の中心**。

→ `iphone-tilt` は画像 1024 の中で画面が `x=99.7〜913`（中心 506.3）にある。
表示幅 2500（2.441 倍）なら画面の中心は `x + 1236`。ここから逆算して置く。

`iphone-flat` は画面がほぼ画像の中央にある（中心 516.5, 511.5 ≒ 512, 512）ので、
**回転させても画面の中心は要素の中心とほぼ一致する**。こちらは `x + w/2` で置ける。

### 回転方向で、つなぎの 1 枚目に入る量が変わる

左回りだと左上の角が張り出して端末の上部が入り、右回りだと左下の角が張り出して
下部だけが入る。**同じ角度でも見え方が変わる**ので、方向を変えたら位置も調整する。

### 端末を大きくすると、下の UI が中途半端に切れる

タブバーの上半分だけが残るような切れ方が一番見苦しい。

→ 切るなら**完全に画面外へ抜く**。中途半端に残さない。

## 描画

### 矢印が黒い塊になる

CSS で `.arrow path { fill: ... }` とすると**線の path にも fill が当たり**、
曲線とその弦で囲まれた面が塗り潰される。

→ 線と頭で**クラスを分ける**。`.line { fill: none }` / `.tip { stroke: none }`。

### チェックマークに絵文字を使うと崩れる

`☑` は環境で字形が変わるうえ、線の太さを見出しに合わせられない。

→ 枠は CSS で描き、中のチェックだけ SVG の data URI にする。

## 書き出し

### 非同期の合成が終わる前に撮ってしまう

モックへの流し込みも切り出しも、画像の実寸が要るので非同期。画像の `complete` を
待つだけでは足りない。

→ テンプレートが `window.__ready`（Promise）を公開し、書き出し側がそれを待つ。

### Playwright のバージョンとブラウザが噛み合わない

新しい版を入れると別ビルドのブラウザを要求し、キャッシュがあっても再ダウンロードになる。

→ **キャッシュ済みのブラウザに合うバージョンに固定**する（`~/Library/Caches/ms-playwright/` を見る）。

### エディタをサーバー越しに開くと画像が全滅する

`content.js` の画像パスがリポジトリの外（`../../apps/...`）を指していると、
配信ルートより上に出られず 404 になる。`file://` では動くので気づきにくい。

→ 配信の基点を**素材が入る範囲まで上げる**。

## 素材

### 白い面で矩形を測ると、カードの下端が上にずれる

`measure_cards.py` は「ほぼ白」の行で帯を拾うので、カード下部の細い文字が並ぶ行で
判定が落ちる。そのまま切り出すと**文字が切れる**。

→ 出た値はカードの実際の下端まで少し広げてから使う。

### LP 用に縮小した画像を使うと甘くなる

620px 幅の画像を端末モックの画面（1000px 超）に引き伸ばすと、UI の細線が潰れる。

→ シミュレータから撮った原寸を使う。
