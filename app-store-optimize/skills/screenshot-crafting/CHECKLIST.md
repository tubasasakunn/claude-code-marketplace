# 提出前チェックリスト

## A. 仕様（必須 — 1つでも落ちると提出不可/表示崩れ）

- [ ] iPhone 6.9" セットがある（1260×2736 / 1290×2796 / 1320×2868 のいずれかに完全一致）
- [ ] iPad対応アプリの場合、iPad 13" セットがある（2064×2752 / 2048×2732）
- [ ] 各セット 1〜10枚、PNG または JPEG
- [ ] 全枚が同一オリエンテーション（原則縦向き）
- [ ] 提出直前に公式仕様ページで寸法を再確認した（デバイス追加で変わることがある）

## B. 審査安全性（必須 — 落ちるとリジェクト）

- [ ] 全枚に実際のアプリUIが写っている（スプラッシュ/ログイン/タイトルのみの枚がない）
- [ ] UI要素を省いた「盛り」加工をしていない（実機の見た目そのまま）
- [ ] iPadスクショはiPad実解像度で撮影（iPhone画像の流用・引き伸ばしでない）
- [ ] 価格・割引・期間限定の文言を焼き込んでいない
- [ ] 検証不能な主張（「世界初」「No.1」）がない。実績数値は証明可能
- [ ] 表示データは架空（実在人物・実在サードパーティコンテンツ・他社商標が写っていない）
- [ ] Android UI・非Apple端末・自作改変デバイスフレームがない（フレームはApple公式ベゼル無改変のみ）
- [ ] テスト広告・「beta」「Coming Soon」・プレースホルダ文字列の残留がない
- [ ] 表現が4+相当（過激な描写がない）
- [ ] ステータスバーが整っている（フル電波・フルバッテリー、時刻9:41推奨）

## C. デザイン品質（推奨 — 落ちるとCVRが下がる)

- [ ] squintテスト: サムネイル幅（約120〜150px）に縮小して見出しが読める
- [ ] 1枚1メッセージになっている
- [ ] 1枚目がヒーロー（価値提案）で、ログイン/空画面/アプリ名の繰り返しでない
- [ ] 最初の3枚だけで「何ができるか・なぜ良いか・何が違うか」が伝わる
- [ ] キャプションは日本語16文字以内/英語6語以内、ベネフィット表現
- [ ] 実UIが画面の50%以上、テキストが20%以下
- [ ] 全枚でフォント・色・レイアウト言語が一貫（DESIGN.md準拠）
- [ ] テキストと背景のコントラストが十分
- [ ] 矢印は1枚1本まで、装飾過多でない
- [ ] 最終枚に社会的証明（または検証可能な事実訴求）がある
- [ ] 日本語ストア向けは日本語キャプション（英語直訳でない）

## D. 設計書

- [ ] SCREENSHOTS.md に全枚の役割・文言・画面・レイアウトが記録されている
- [ ] 画像が `screenshots/<locale>/` に配置され、命名が deliver のデバイス判定と整合
