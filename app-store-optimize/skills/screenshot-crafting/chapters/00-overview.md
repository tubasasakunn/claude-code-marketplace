# 第0章: 序章 — スクショは「広告」である

## なぜこの工程が重要か

App Store の検索結果ページには、アイコン・アプリ名・評価と並んで**最初の3枚のスクリーンショットがそのまま表示される**（縦向きの場合。横向きは1枚のみ）。大半のユーザーは詳細ページを開く前に、この一覧表示だけで継続/離脱を判断する。

判断の前提となる実証データ:

- 製品ページ滞在時間の中央値は**7秒**、閲覧枚数の中央値は**2.4枚**（Storemavenアイトラッキング）
- スクロール率は約**17%**（SplitMetrics/ŠKODA実測）。「もっと見る」タップは2%未満
- スクショ最適化単体でCVR **+13〜40%** の改善事例が多数（Angry Birds 2 縦向き化+13%、Headspace +34%、ZiMAD +32%）
- 日本語ローカライズ済みスクショは非英語圏でCVR +20〜40%

結論: **最初の3枚を「三連広告」として設計する**。1枚目単体でも成立し、3枚並びでも一貫したストーリーになる二重構造にする。

## 制作の全体像

```
入力: CONCEPT.md（何のアプリか・コア体験）+ DESIGN.md（色・フォント・世界観）+ 実機UI
  ↓
① 仕様確認（01-specs.md）— サイズ・枚数を確定
② ストーリーボード（02-storyboard.md）— 5〜7枚の役割分担を決める
③ 各枚のレイアウト（03-layout.md）— 構図・視線誘導を決める
④ 文言（04-copy.md）— キャプションを書く
⑤ 審査安全性チェック（05-review-safety.md）— 地雷を除去
⑥ 制作・提出（06-automation.md）— 撮影・合成・アップロード
  ↓
出力: SCREENSHOTS.md（設計書）+ 画像一式
```

## SCREENSHOTS.md のテンプレート

設計書として以下を残す。文言変更・A/Bテスト・多言語展開の起点になる。

```markdown
# SCREENSHOTS.md — アプリ名

## 方針
- 訴求軸: （CONCEPT.mdのコア体験から一言で）
- トーン: （DESIGN.mdから: 色・フォント・背景処理）
- フレーム: あり（金融/ヘルスケア系）/ なし（フルブリード、それ以外の既定）

## 構成
| # | 役割 | キャプション | 画面 | レイアウト |
|---|------|------------|------|-----------|
| 1 | ヒーロー | （16字以内） | （どの画面のUI） | テキスト上/デバイス下 |
| 2 | ベネフィットA | ... | ... | ... |
| 3 | 差別化+ズーム | ... | ... | ルーペ表現 |
| 4 | サブ機能 | ... | ... | テキスト下/デバイス上 |
| 5 | クロージング | ... | ... | バッジ中央 |

## 検証記録
- squintテスト: 済/未
- CHECKLIST: 済/未
```

## 基本原則（全章に共通）

1. **1枚1メッセージ** — 複数の機能・ベネフィットを1枚に詰めない
2. **実UIをそのまま** — 盛らない・省かない・架空データを仕込む（実在人物NG）
3. **サムネイルで読めることが絶対条件** — 迷ったら文字を大きく
4. **ブランド一貫性** — 全枚で同じフォント・色・レイアウト言語（DESIGN.mdを継承）
5. **小手先の文言変更より構成の質** — 個人開発のA/Bテスト実例では、微修正より抜本的なテンプレート刷新の方が効果が出ている
