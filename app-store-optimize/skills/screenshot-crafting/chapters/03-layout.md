# 第3章: 1枚の中の構図

## 基本レイアウトと数値基準

基本形は「**キャプション上部 + デバイス/UI下部**」。ただし全枚同じだと単調なので、「フルデバイス+テキスト上」と「部分デバイス+テキスト下」を交互に混ぜる。

| 項目 | 基準 |
|---|---|
| 実UIの面積 | 画面の**50%以上** |
| テキストの面積 | **20%以下**（Google Play公式基準の流用） |
| 見出しフォント | 1290×2796基準で**60〜90px**、ウェイト700〜900、字間タイト |
| サブテキスト | 28〜36px、8〜12語まで（無くてもよい。見出しだけで伝わることが先） |
| キャプション | 折り返しは最大2行。サムネイルで読めなければ失格 |

背景はDESIGN.mdのブランドカラーから: 単色 or 2〜3色グラデーションが既定。ダーク背景+明色テキストはコントラストが高くサムネイルに強い。テキストと背景が近い色になる場合は背景レイヤーか輪郭で分離する。

## デバイスの見せ方

- **フルブリード（フレームなし）**: UI表示面積が最大。多くのカテゴリの勝ちパターン
- **デバイスフレームあり**: 金融・ヘルスケア向け。**Apple公式ベゼルを無改変で使う**（影・反射の追加、傾け、クロップ、ノッチの捏造は Marketing Guidelines 違反。詳細は05章）
- **ブリード（見切れ）**: デバイスを画面端で切ると「続きを見たい」心理でスクロール誘発
- **3D・傾き演出**: ストア掲載には非推奨（サムネイルでUIが読めなくなる）。広告・LP用
- セーフエリア注意: 端に重要なテキスト/UIを置かない（角丸・表示クロップで欠ける）

## 強調テクニック

- **ズームアップ（ルーペ表現）**: 「ユーザーは自分でズームしない」ので、重要なUI部品は作り手が拡大して見せる。拡大円と元位置を線でつなぐ表現が定番
- **フローティングUIカード**: 通知・モーダル・バッジだけを切り出し、影付きで画面外に浮かせる
- **評価バッジ**: 「★4.8 - 5万人が評価」を月桂樹（laurel）で囲むアワード風が定番。**最終枚**に置く

## 視線誘導

- 矢印は**1枚に1本まで**。2箇所以上示したいなら番号ステップ ①②③ に切替
- 人物を使う場合、視線・指先を見せたいUIや次の枚の方向に向ける
- 三分割法: 重要な要素を仮想3×3グリッドの線上に置く

## アンチパターン（これをやると負ける）

1. 1枚に複数機能を詰め込む（1枚1メッセージ違反）
2. コントラスト不足（明背景に白文字等）、テキストがUIに埋没
3. 長文キャプション（見出しであるべきものが本文になっている）
4. 過剰装飾 — コールアウト・グラデーション・影を盛りすぎてUI本体が霞む
5. 視覚的階層の欠如（全要素が同じ重み）
6. 枚ごとにフォント・色・レイアウトがバラバラ
7. セーフゾーン無視、規定外寸法の引き伸ばし
8. 英語のみのテキストで日本のストアに出す（ローカライズ無視）

## 検証方法（squintテスト）

完成画像を検索結果サムネイル相当（幅 約120〜150px）に縮小して表示し、目を細めて見出しが読めるか確認する。読めなければ文字を大きくする。「でかすぎるくらいがちょうどいい」。
