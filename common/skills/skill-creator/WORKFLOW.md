# スキル作成ワークフロー

スキルの作成・修正は4つのフェーズで進行します。

---

## Phase 1: 要件の確定

**目的**: ユーザーの要件を明確にし、スキルの方向性を固める

### 確認項目

AskUserQuestionツールを使用して以下を確認：

#### 基本情報
```
- スキル名（小文字、数字、ハイフンのみ）
- 主な目的・機能
- いつ使用されるべきか（トリガー条件）
- 対象ユーザー（個人用/プロジェクト共有/プラグイン）
```

#### スキルタイプ
```
- リファレンス型: 知識・ガイドラインを提供
- タスク実行型: 特定のアクションを実行
- 分析・レビュー型: コードやデザインを分析
```

#### 実行方式
```
- インライン実行: 会話コンテキスト内で実行
- サブエージェント（fork）: 独立コンテキストで実行
  → エージェントタイプ: Explore / Plan / general-purpose / カスタム
```

#### 呼び出し制御
```
- Claude自動呼び出し: 許可 / 手動のみ（disable-model-invocation）
- /メニュー表示: 表示 / 非表示（user-invocable）
```

#### ツール制限
```
- 使用ツール: 全て / 制限あり（allowed-tools）
  - 読み取り専用: Read, Grep, Glob
  - 特定コマンド: Bash(npm:*), Bash(git:*)
```

#### 引数・フック
```
- 引数を受け取るか: はい / いいえ
- 引数ヒント: 例）[filename] [format]
- ライフサイクルフック: 不要 / 必要（PreToolUse/PostToolUse/Stop）
```

### Phase 1 完了条件

- [ ] スキルの目的が明確
- [ ] タイプ（リファレンス/タスク/分析）が決定
- [ ] 実行方式（インライン/fork）が決定
- [ ] 呼び出し制御が決定
- [ ] ツール制限の有無が決定

---

## Phase 2: 情報の構造化

**目的**: 入力情報を整理し、適切なファイル構成を設計する

### ファイル構成の原則

**SKILL.mdは常にインデックスとして機能**:
- 全情報の要約を含む
- 詳細は別ファイルへ参照リンク
- 500行以下を厳守

### 構成パターン

#### パターンA: シンプルスキル（情報量が少ない）
```
skill-name/
└── SKILL.md          # 全ての内容を含む（〜200行）
```

#### パターンB: 標準スキル（情報量が中程度）
```
skill-name/
├── SKILL.md          # インデックス + 要約（〜300行）
└── REFERENCE.md      # 詳細リファレンス
```

#### パターンC: 複雑なスキル（情報量が多い）
```
skill-name/
├── SKILL.md          # インデックス + 要約（〜300行）
├── WORKFLOW.md       # ワークフロー詳細
├── CHECKLIST.md      # チェックリスト
└── reference/
    ├── api.md
    └── examples.md
```

### 分割の判断基準

| 条件 | 分割先 |
|:-----|:-------|
| 反復的なワークフロー | WORKFLOW.md |
| 検証・品質チェック | CHECKLIST.md |
| APIリファレンス | REFERENCE.md または reference/ |
| 具体例の集積 | EXAMPLES.md |
| ドメイン固有の知識 | 該当ドメイン名.md |

### Phase 2 完了条件

- [ ] ファイル構成パターン（A/B/C）が決定
- [ ] 各ファイルの役割が明確
- [ ] SKILL.mdがインデックスとして機能する設計
- [ ] 参照は1レベルの深さまで

---

## Phase 3: スキル構成の設計

**目的**: skill-creator/の全情報を参照し、最適なスキル構成を決定する

### 参照すべきドキュメント

作成前に以下を確認：

1. **[FRONTMATTER.md](FRONTMATTER.md)** - フロントマター設定
   - name, description の書き方
   - context, agent, allowed-tools の設定
   - hooks の設定方法

2. **[BEST-PRACTICES.md](BEST-PRACTICES.md)** - ベストプラクティス
   - 簡潔さの原則
   - 段階的開示パターン
   - 例とテンプレートの書き方

3. **[EXAMPLES.md](EXAMPLES.md)** - 具体例集
   - 類似スキルの参考

4. **[VALIDATION-CHECKLIST.md](VALIDATION-CHECKLIST.md)** - 検証項目
   - 公開前の確認事項

5. **[ADVANCED-PATTERNS.md](ADVANCED-PATTERNS.md)** - 高度なパターン
   - サブエージェント、動的コンテキスト

### 設計チェックリスト

#### フロントマター設計
- [ ] `description` に「何をするか」+「いつ使うか」を含む
- [ ] `description` は三人称で記述
- [ ] 必要に応じて `context: fork` を設定
- [ ] 必要に応じて `allowed-tools` を制限
- [ ] 必要に応じて `disable-model-invocation: true` を設定

#### コンテンツ設計
- [ ] タスク型スキルには明確なワークフローを含む
- [ ] エージェント型には反復可能なチェックリストを含む
- [ ] 終了条件を明確に定義
- [ ] **クイックリファレンスセクションを含む**（よく使う情報の要約）
- [ ] 詳細情報への参照リンクを配置

### Phase 3 完了条件

- [ ] フロントマター設定が決定
- [ ] SKILL.mdの構成（セクション）が決定
- [ ] 参照ファイルの内容が決定
- [ ] ベストプラクティスとの整合性を確認

---

## Phase 4: スキルの作成

**目的**: 設計に基づいてスキルファイルを作成する

### SKILL.md作成の原則

#### 1. インデックスとして機能させる

```markdown
# スキル名

## 概要
1-2文で目的を説明

## ワークフロー
ステップの概要（詳細は別ファイル参照）

## クイックリファレンス
よく使う情報の要約

## 詳細ドキュメント
- [WORKFLOW.md](WORKFLOW.md) - 詳細ワークフロー
- [CHECKLIST.md](CHECKLIST.md) - 検証チェックリスト
```

**クイックリファレンスの重要性**:
- SKILL.mdを読むだけで基本的な作業ができるようにする
- 参照ファイルを開かなくても最頻出の情報にアクセス可能
- テンプレート、決定フロー、コマンド例など実用的な情報を含める

#### 2. エージェント型スキルの必須要素

```markdown
## ワークフロー

### ステップ1: [ステップ名]
[指示]

完了条件:
- [ ] 条件1
- [ ] 条件2

### ステップ2: [ステップ名]
...

## 終了条件
すべてのタスクが完了したら終了:
- [ ] 最終条件1
- [ ] 最終条件2
- [ ] 最終条件3
```

#### 3. 簡潔さの原則

- **Claudeが知っていることは書かない**
- **500行以下を厳守**
- **具体的な指示 > 曖昧な説明**
- **1つのデフォルト > 複数の選択肢**

### 品質チェック

作成後、[VALIDATION-CHECKLIST.md](VALIDATION-CHECKLIST.md)で検証：

#### 必須チェック
- [ ] フロントマターが正しい形式
- [ ] `name`が命名規則に従っている
- [ ] `description`が「何を」+「いつ」を含む

#### 品質チェック
- [ ] SKILL.mdが500行以下
- [ ] 時間依存情報がない
- [ ] 用語が一貫している
- [ ] 参照は1レベルまで

#### エージェント型特有
- [ ] 反復可能なワークフローがある
- [ ] チェックリストで進捗管理できる
- [ ] 終了条件が明確

### Phase 4 完了条件

- [ ] SKILL.mdが作成完了
- [ ] 参照ファイルが作成完了（必要な場合）
- [ ] VALIDATION-CHECKLISTの必須項目をパス
- [ ] 実際のタスクでテスト済み

---

## ワークフロー全体の終了条件

スキル作成・修正が完了したと判断する条件：

1. **Phase 1-4がすべて完了**
2. **SKILL.mdがインデックスとして機能している**
3. **エージェント型の場合、反復可能なワークフローを含む**
4. **終了条件がSKILL.md内に明記されている**
5. **VALIDATION-CHECKLISTの必須項目をパス**
6. **実際のタスクでテストし、期待通り動作する**

## クイックリファレンス

### フロントマター決定フロー

```
副作用がある？ → disable-model-invocation: true
会話履歴不要？ → context: fork
読み取りのみ？ → allowed-tools: Read, Grep, Glob
ユーザー呼び出し不要？ → user-invocable: false
```

### ファイル分割の目安

```
〜200行 → SKILL.mdのみ
〜400行 → SKILL.md + REFERENCE.md
400行〜 → SKILL.md + 複数ファイル
```

### description テンプレート

```yaml
# リファレンス型
description: [対象]の[ガイドライン/規約/パターン]を提供します。[トリガー条件]について質問された場合に使用してください。

# タスク実行型
description: [タスク]を実行します。[トリガー条件]の場合に使用してください。

# 分析・レビュー型
description: [対象]を分析/レビューします。[トリガー条件]について質問された場合に使用してください。
```
