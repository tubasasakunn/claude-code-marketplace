# 7 つの軸

レイアウトは「型を1つ選ぶ」ものではなく、**7 つのダイヤルをどこに合わせるか**で決まる。
既存アプリの構図はすべてこの座標で記述できる。`patterns.md` の 44 型は、
頻出する組み合わせに名前を付けたもの。

迷ったら **軸1=見切れ / 軸2=上 / 軸3=単色 / 軸4=0° / 軸5=接地 / 軸6=なし / 軸7=1枚完結**
に置く。これが最も普及した既定形（P-01）で、カテゴリを問わず成立する。

---

## 軸1 — 実UIの見せ方

実UIの占有面積を決める、最も影響の大きい軸。

| 値 | 実UI面積 | 備考 |
|---|---|---|
| フルブリード | 100% | 加工ゼロ。文脈も伝わらない |
| 画面幅超え（両端切れ） | 最大 | 端末の輪郭が失われ「画面の一部」に見える |
| 見切れ（下端で切る） | 大 | 既定。限られた高さに実UIを最大量入れられる |
| フレームなし（全身） | 中 | 背景と画面の境界が曖昧になりやすい |
| フレーム付き（全身） | 小 | 製品らしさ・堅実さ。ベゼルが面積を食う |
| 複数台 | 小 | 幅は示せるが1台あたりが小さい |
| 部分拡大のみ | — | 注釈と組み合わせて使う |

**基準**: 実UIは画面の 50% 以上、テキストは 20% 以下。
フレームを付けても 6.9″ で幅 80% なら実UI面積は約 52% で基準を満たす。

**フレームの有無に正解は無い。** 実測17本はほぼ半々（有：Day One・Calm・Spotify・Reflectly・
Bear・Upmind・Balance ／ 無：Headspace・Strava・Otter.ai・Pinterest・Obsidian・Finch・Awarefy）。
両方作って並べて決める。

---

## 軸2 — キャプション位置

| 値 | 備考 |
|---|---|
| 上 | **実測17本すべてがこれ**。事実上の標準 |
| 下 | 定説として語られるが実測に例が無かった |
| 中央 | 実UIが無い枚（ブランドパネル等）で使う |
| 画面に重ねる | アプリ自身の余白に置く。半透明の幕が必要 |
| 左右分割 | 横位置と相性がよい。縦だと端末が細くなる |
| 回転同調 | 端末と同じ角度に振る。日本語は読みにくくなる |
| なし | UI そのものが売りのときだけ |

全枚を同じ位置にすると単調。**上下を交互に混ぜる**のが定石だが、
実測では上部固定が支配的なので、単調さは軸3（色）や軸4（回転）で崩す方が安全。

---

## 軸3 — 背景（地）

サムネイルで最初に認識されるのは色面。彩度が高いほど検索結果で目に留まる。

| 値 | 備考 |
|---|---|
| 単色（ブランドカラー） | 最も強い。枚ごとに色を変える運用も定番 |
| グラデーション | 静けさ・時間の流れを表現できる |
| 紙地（白〜オフホワイト） | エディトリアル。サムネイルで沈むリスク |
| ダーク | 端末の黒より明るく取ること（後述） |
| 実写 | **実測17本に地が実写の例は1本も無かった** |
| ブロブ（白地＋有機的な色面） | 日本のAI・メンタル系で頻出 |

**白/淡色の地は避ける**か、文字を十分に太くする。App Store の背景に溶ける。

---

## 軸4 — 回転

端末を振るかどうか。可読性と動きが交換される。

| 値 | 角度 | 備考 |
|---|---|---|
| 0° | — | 既定。UIが最も読める |
| 微傾斜 | 5〜10° | 「置かれた物」の質感。5°未満なら付けない方がよい |
| 中傾斜 | 約20° | 可読性と動きの釣り合う点 |
| 大傾斜 | 30°超 | UIは読めない。雰囲気を売る枚に限る |
| 隅差し | 15〜20°＋部分見せ | 文字と余白で語りたいとき |

**回転の対象は2種類ある**: 端末だけを振るか、見出しごと全体を振るか（回転同調）。
後者は1枚を1つの絵として作れるが、回転した日本語は読みにくい。

> **審査上の注意**: Apple Marketing Guidelines は端末画像の改変（傾け・影・反射の追加）を
> 禁じている。Calm・Spotify・Reflectly・Upmind が実際に採用しており実務上は通っているが、
> **規約上の安全が保証されているわけではない**。提出する枚に使うときは見直すこと。

---

## 軸5 — 浮遊

回転とは独立に効く。接地させるか、影で浮かせるか。

| 値 | 備考 |
|---|---|
| 接地 | 影なし。最も素直 |
| 影付き浮遊 | 平坦さを崩せる。濃くしすぎると安っぽい |
| カード・カスケード | UIの断片を斜めに階段状へ。どれも読めなくなる |
| 扇状 | 複数台を扇に開く。幅は示せるが1枚目には向かない |

軸4 と組み合わせると4通り（傾けない×浮かせない／傾けるだけ／浮かせるだけ／両方）。
**「斜め重ね」を1つの型として扱うと、この区別が潰れる**（実際に一度潰した）。

---

## 軸6 — 比較

入力と出力が明確に違うアプリでは強い武器になる。

| 値 | 備考 |
|---|---|
| なし | 1状態のみ |
| 左右（2端末＋矢印） | 横位置と相性がよい。視線移動が自然 |
| 上下 | 縦位置で素直。矢印の縦方向は誘導が弱い |
| 斜め分割 | 面積を無駄にしない。**両面が似た色だと境界が消える** |

日本のツール系アプリで頻出。手描き風の曲線矢印を添えるのが定番。

---

## 軸7 — 枚をまたぐ連続性

| 値 | 備考 |
|---|---|
| 1枚完結 | 既定。最悪ケース（1枚しか露出しない）に強い |
| 枚ごと色替え | 構図は固定し地の色だけ回す。安全に単調さを崩せる |
| セット漸進グラデ | 地の色が枚をまたいで移り変わる。パノラマより安全 |
| パノラマ連結 | 2〜3枚で1つの絵。**最悪ケースに弱い** |
| 文の継続 | 1枚目→2枚目で文が繋がる。同じく最悪ケースに弱い |

**Apple が保証しているのは「プレビュー動画が無ければ最初の1〜3枚」だけ。**
最悪ケースは1枚なので、**各枚が単独で成立することを優先し、連続性はボーナスに留める**。

パノラマを使う場合、ストア表示ではスクショの間に間隔が入るため、設計時にその分の余白を
空けておかないと絵がつながらない（iPhone X 基準で **56px**。迷ったらこの値に統一）。
さらにプロダクトページで完璧に合わせると検索結果側では比率が違うためずれる。
