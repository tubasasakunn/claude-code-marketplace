# 踏んだ罠

実際に発生させたものだけを書く。すべて「画面上は正常に見えるのに壊れている」類なので、
**作った画像は必ず自分の目で見る**（コンタクトシートに並べて Read する）。

---

## 作図

### ダイナミックアイランドの二重描画

`material/screens/` のスクショは**実機のステータスバーごと写っている**。
端末フレームを描くときに島も描くと、二つが重なって太った黒い塊になる。

**島は描かない。** 「フレームなのに島が無い」と思って足すと再発する。
`store_layout_kit.phone()` にコメントで残してある。

### 高さのパーセント指定が 0 に潰れる（CSS）

高さが未定義の flex 親に対する子の `height: %` は 0 になる。
CSS でタイル図を描くときに見出しのバーが全部消えた。**親の寸法から計算した値で指定する。**

### 集中線の内径が小さいと線が端末の脇から生える

内径を端末の**半対角**より小さく取ると、端末を貫通した線の残りだけが左右に見え、
「線が脇から生えている」ように見える。`r_in > sqrt((w/2)² + (h/2)²)` を満たすこと。

### 斜め分割は両面が似た色だと破綻する

2つの画面がどちらも白いと、斜めの境界が消えて2つの本文が混ざり判読不能になる。
**片面に色を被せて分離する**（アルファ 200 前後。150 程度では白文字が読めない）。

### ダークモード枚を近黒の地に置くと全部が潰れる

暗い画面 + 黒いベゼル + 近黒の地 = 一塊の黒。「ダークモードを見せる」目的を果たさない。
**地はダークのまま端末の黒より明るく取る**（例: RGB 46,51,60）。
Headspace が濃紫の地にダーク画面を置いているのと同じ理屈。

### 回転同調テキストは白文字が白い画面に重なる

見出しと端末を同じ角度に振るとき、文字が画面の上に乗ると読めない。
**文字は端末より完全に上（または外）へ逃がす。**

### 端末を隅から差し込むとき、出しすぎる／隠しすぎる

中心を画面幅の 1.0 倍に置くとほぼ全部がキャンバス外に出る。**0.84 前後**で半分見える。

### 素材の高さがばらつくと単純な crop で黒帯が出る

レイアウトのバリエーション画像は高さが不定（実例では 1441〜4744px）。
`cover()`（埋めるように拡縮して切り抜く）を使う。

### 小さな切り抜きはステータスバーしか写らない

画面の上端を切ると中身が写らない。**画面ごとに「中身が写っている帯」の縦位置を指定する。**

### 拡大した部品を元位置の近くに置くと二重に見える

フローティングUIカードは、元の位置から十分離す。近いと「壊れた重複」に見える。

## 素材

### 参考にする競合スクショが古い

**iTunes Lookup API は古いスクリーンショットを返すことがある**（Calm では2017年当時のセット）。
分析の前に、取得した画像が現行の店頭表示か確認する。詳細は `evidence.md`。

### 同じシードで撮った素材は「毎日ちがう」を訴求できない

QA 用に同一データで撮ったレイアウト集は、構成の違いは出るが**内容が全部同じに見える**。
バリエーションを売りにする枚は、複数シードで撮り直す。

### アプリ名の取り違え

App ID からの取得は、返ってきた画像が本当にそのアプリか目で確認する
（実際に別アプリのマニュアルが返ってきたことがある）。

## 審査

### 合成UIは実機の見た目と異なる（2.3.3）

通知バナー・ウィジェットを描き起こしたものは実機の見た目ではない。
**提出するなら実機で撮り直す。** 実UIに存在しない部品を作るのも同じ。

### ログイン画面・空状態・設定画面

1枚目に置かない。空のリスト・プレースホルダはコンバージョンを落とす。

### 端末画像の改変（Marketing Guidelines）

**傾け・影・反射の追加は端末画像の改変として禁じられている。**
Calm・Spotify・Reflectly・Upmind が実際に採用しており実務上は通っているが、
規約上の安全が保証されているわけではない。提出する枚に使うときは見直す。
ベゼルは Apple 公式素材を無改変で使うのが最も安全。

### 根拠のない数値・順位

「No.1」「効果があります」は審査 2.3 と景表法の両方に触れる。
**自社で証明できる数値のみ。** 受賞が無い段階は「広告なし」「登録不要」など
検証できる事実で代替する。医療・メンタル系は効能を謳わない語彙に置き換える
（実例では「スコア化」「気づき」「整理」などの中立語、あるいは文脈自体をゲームへ転換）。

### iPad 素材の手抜き

iPhone 画像の引き伸ばし流用は弾かれる。iPad 実解像度で撮り直す。

## 検証

### squint テスト

完成画像を検索結果サムネイル相当（幅 120〜150px）に縮小して、見出しが読めるか確認する。
読めなければ文字を大きくする。**「でかすぎるくらいがちょうどいい」。**

### コンタクトシート

型ごと・セットごとに1枚の画像へ並べて目視する。
1枚ずつ見ると気づかない不統一（フォント・色・余白・キャプション位置）が一目で分かる。

```python
from PIL import Image, ImageDraw
ims = [Image.open(f) for f in files]
for im in ims: im.thumbnail((190, 600))
sh = Image.new("RGB", (len(ims)*200+10, max(i.height for i in ims)+26), (22,24,26))
d = ImageDraw.Draw(sh)
for i, im in enumerate(ims):
    d.text((10+i*200, 3), labels[i], fill=(238,238,232)); sh.paste(im, (10+i*200, 20))
sh.save("sheet.png")
```
