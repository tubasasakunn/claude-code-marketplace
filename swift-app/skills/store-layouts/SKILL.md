# ストア画像の構図（store-layouts）

ストア画像は「アプリ画面の記録」ではなく**検索結果に並ぶ広告**。
Apple が保証しているのは「プレビュー動画が無ければ最初の 1〜3 枚」だけで、
**最悪ケースは1枚しか見えない**。だから 1 枚目が単独で完結していることが最優先になる。

このスキルは、その 1 枚をどう組むか（構図）に絞って、型・指針・部品・落とし穴を提供する。
文言そのものの型は `/app-store-optimize:aso`、提出パイプラインは `/swift-app:release-assets` の担当。

## 使いどころ

- ストア画像のレイアウトをこれから決める
- 候補を複数作って並べて選びたい
- 既存のストア画像を診断したい（面積比・向き・1枚目の妥当性）
- 縦向き／横向き、フレームの有無、傾けるかを判断したい

## 進め方

### 1. 診断（既存画像があるとき）

```bash
cd release/<version>/img && for f in *.png; do
  echo -n "$f: "; sips -g pixelWidth -g pixelHeight "$f" | tail -2 | tr -d '\n' | tr -s ' '; echo
done
```

見るのは 4 点。

1. **向き** — 横向きなら **App プレビュー動画があるか**を確認する。
   動画なしの横向きは「ページ全体のエンゲージメントを損なう」とされる構成
   （`reference/evidence.md`）。ゲーム以外の上位アプリは 95% が縦向き
2. **実UIの面積** — 50% を下回っていないか
3. **1枚目** — 単独で「何ができるアプリか」が伝わるか。
   課題提起だけ・ログイン画面・空状態になっていないか
4. **セット内の一貫性** — 書体・色・キャプション位置が揃っているか

### 2. 型を選ぶ

**`reference/axes.md` を読んで 7 軸のどこに合わせるかを決める。**
軸の組み合わせが構図になる。既定値（迷ったらこれ）:

> 見切れ / キャプション上 / 単色の地 / 回転 0° / 接地 / 比較なし / 1枚完結

そのうえで `reference/patterns.md`（44 型）から候補を挙げる。
**セットの並びは、権威（受賞・掲載・実数）があるかで分岐する。**

| 状況 | 1枚目 | 以降 |
|---|---|---|
| 権威がある | P-35 権威パネル（実測の最多数派） | 中核ベネフィット → 差別化 → 周辺 |
| 権威がない | 最大のベネフィットを直球で（P-01） | 中核操作 → 差別化 → 一覧 → ダークモード → 検証できる事実 |
| 玄人向け | P-02 フルブリード（説明ゼロ） | 同じ調子で並べる |

枚数は 5〜7 枚。10 枚埋めるために弱い枚を足すとセットの平均品質が落ちる。
**ダークモード対応なら1枚入れる**（Apple が公式に推奨している唯一の構図上の助言）。

### 3. 作る

```bash
cp .claude/skills/store-layouts/store_layout_kit.py scripts/
```

`store_layout_kit.py` は**そのまま使える描画部品**。`appstore.config.json` の
`brand`（色・ワードマーク）と `fonts` を読み、`material/screens/` の素材を扱う。

| 部品 | 用途 |
|---|---|
| `phone(src, w, framed=)` | 端末モックアップ。**島は描かない**（素材に写っている） |
| `rot(img, deg)` / `floated(img)` / `place(base, obj, center, deg=, float_=)` | 回転・影付き浮遊・配置 |
| `cover(img, w, h, top=)` | 高さが不定の素材を切り抜く |
| `vgrad` / `hgrad` | グラデーション地 |
| `text_block` / `text_layer` / `marker` / `checklist` | 文字組み。`text_layer` は回転させたい文字用 |
| `badge` / `curve_arrow` / `burst` / `loupe` | 円形注釈・曲線矢印・集中線・ルーペ |
| `pict(kind, size, color)` | ピクトグラム（moon / bed / train / mic / clock / book） |

**スクリプトはアプリごとに書く。** `examples/make_pattern_samples.py` は
44 型すべてを組んだ実例（実際に動いたもの）で、汎用化された道具ではない。
**該当する型の関数をコピーして、素材名・文言・色を差し替える**のが想定した使い方。

寸法は 6.9″ の実寸から動かさない（ASC は解像度でシェルフを判定する）。

```
縦 1320 × 2868   横 2868 × 1320
```

文字の目安（1320px 幅基準）:

| 要素 | 大きさ |
|---|---|
| 見出し | 96〜112px / ウェイト 900 / 字間 −3〜−5 |
| 補足 | 40〜46px / ウェイト 500 |
| 1行の文字数 | 日本語 16 文字以内・折り返しは 2 行まで |

改行位置は**手で決める**（自動折り返しに任せると句読点が行頭に来る）。

### 4. 見る

**必ず自分の目で確認する。** 作図の壊れは「画面上は正常に見えるのに壊れている」類が多い。

- コンタクトシートに並べて Read する（コードは `reference/traps.md`）
- **squint テスト**: 幅 120〜150px に縮小して見出しが読めるか
- フレームの有無を両方作って並べる（実測はほぼ半々。正解のある軸ではない）

### 5. 昇格

選んだ型を `release/<version>/img/` の本番画像へ。以降は `/swift-app:release-assets` と
`/swift-app:release-version` の担当。

---

## 判断が要る 3 点

### 縦向きか横向きか

**動画が無いなら縦向き。** 横向きの利点（直接インストール +11%、検索 CVR の事例 +42%、
動画視聴率 2 倍）はすべて動画の存在を前提にしている。
ゲーム以外の上位アプリは 95% が縦向き。数字で決めたいなら PPO でテストできる
（Apple 自身が推奨している用途）が、treatment は最大3本で有意差にはトラフィックが要る。

### フレームを付けるか

**正解は無い。** 実測17本はほぼ半々。両方作って並べて決める。
フレームを付けても幅 80% なら実UI面積は約 52% で「50% 以上」の基準は満たす。

### 傾けるか

平坦さを崩す最も効く手だが、**Apple Marketing Guidelines は端末画像の改変
（傾け・影・反射の追加）を禁じている**。実在アプリが多数採用しており実務上は通っているが、
規約上の安全が保証されているわけではない。提出する枚に使うなら見直すこと。
安全側に寄せるなら、傾けずに軸3（枚ごとの色替え）で単調さを崩す。

## 終了条件

- [ ] `reference/axes.md` の 7 軸で、選んだ型の座標を言える
- [ ] 1 枚目が単独で「何ができるアプリか」を伝えている
- [ ] 実UIの面積が 50% 以上、テキストが 20% 以下
- [ ] 向きが揃っている（混在させない）。横向きなら動画がある
- [ ] ダークモード対応なら1枚入っている
- [ ] 書体・色・キャプション位置がセット内で揃っている
- [ ] squint テスト（幅 120〜150px）で見出しが読める
- [ ] 合成UI・実機と異なる画面・根拠のない数値が無い
- [ ] 寸法が 6.9″ の実寸（縦 1320×2868 / 横 2868×1320）
