# アーキテクチャ・拡張性規約

「小さく始めて、育っても壊れない」ための構造の定石。iOS アプリ（SwiftUI 前提）向け。
大きな判断（レイヤ追加・依存追加・モジュール分割）は必ず `/adr` で記録する。

## 基本形：SwiftUI ネイティブの MV 構成

- 標準は **View + `@Observable` モデル**の 2 層。画面ごとに ViewModel を機械的に
  量産しない（SwiftUI では View 自体が軽量な view model の役割を果たす）。
- `@Observable` モデルは「**画面の写像**」ではなく「**機能・ドメインの単位**」で切る
  （例：`RecordingSession`、`Library`、`PurchaseState`）。複数画面が同じモデルを
  `@Environment` で共有する形が基本。
- 手続きが複雑な画面（フォーム・ウィザード等）に限り、画面専属の `@Observable`
  状態オブジェクトを許容する。「全画面 MVVM」への統一はしない（ADR で覆さない限り）。

## 依存注入は @Environment で

- サービス（永続化・API クライアント・課金・通知など）は `@Observable` クラスとして
  実装し、アプリルートで生成して **`@Environment` で注入**する。
- **シングルトン（`static let shared`）を新設しない**。既存 SDK のシングルトン
  （`UserDefaults.standard` 等）は薄いサービス型で包んで注入する。
  例外は状態を持たない純粋なユーティリティのみ。
- View やモデルの中で依存を **直接 `init()` しない**（テスト・プレビューで
  差し替え不能になる）。生成はアプリルート（composition root）1 箇所に集める。

## protocol 境界は「差し替えが現実に要る」場所だけ

- **protocol を先回りで切らない**。実装が 1 つしかない protocol は抽象の水増し。
  まず具象型で書き、2 つ目の実装（モック・別バックエンド）が現実に必要になった時点で切る。
- 切る価値がある典型：外部 I/O（ネットワーク・課金・位置情報）、プレビュー/テストで
  本物を動かせないもの（カメラ・録画）。
- 抽象化の代替手段を先に検討する：クロージャ 1 本の注入・enum による分岐・
  ジェネリクス。protocol + existential（`any`）は最後の手段。

## 変更に強いコードの原則

- **継承より合成**。class 継承で振る舞いを差し替えない（`final` が基本）。
  共有したい振る舞いは protocol extension・ジェネリック関数・部品 struct の合成で。
- **不正状態を型で潰す**。optional の組・Bool フラグの組で状態機械を表現しない。
  enum + associated value に畳む（`.claude/rules/swift-api-design.md`）。
- **一方向の依存**。`Design/` `Resources/` のような基盤層はドメインを知らない。
  ドメインは UI を知らない。逆流 import を見つけたら構造の警報。
- 機能追加は「新しい型・新しいファイルを足す」形に寄せ、既存型の肥大化
  （巨大 switch・God オブジェクト）で受けない。500 行分割ルールはこの検知器。

## ディレクトリとモジュール

- フォルダは**機能単位**（`Recording/`, `Library/`, `Settings/`）＋横断の基盤
  （`Design/`, `Resources/`, `Services/`）。「Views/ Models/ 全部入れ」の
  種類別フォルダにしない。
- SPM ローカルパッケージへの分割は、ビルド時間かターゲット共有（widget 等）の
  実需が出てから。テンプレート段階では単一ターゲット + フォルダ規律で十分（ADR に残す）。
- 分割したら並行性設定はモジュール単位で分ける：UI 系は MainActor デフォルト隔離、
  ドメイン・I/O 系のコアは nonisolated デフォルトが定石。

## 外部依存（SPM パッケージ）の基準

- 追加は「自作すると明らかに割に合わない」ものだけ。UI 小物・数十行で書ける
  ユーティリティのために依存を増やさない。
- 採用基準：メンテが生きている・iOS 最新 SDK 追従・Swift Concurrency 対応
  （Sendable 注釈）・ライセンス確認。採用したら理由と代替案を ADR に記録する。
