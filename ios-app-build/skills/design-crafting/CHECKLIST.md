# 最終診断リスト

DESIGN.md が完成したとユーザーに提示する前に、以下を横断チェックする。各項目の詳細は元になった章を参照。

## コンセプトとの一貫性(第1章)
- [ ] 核メタファーはCONCEPT.mdの言葉から実際に導かれているか(他アプリからの借用になっていないか)
- [ ] 「何がアクセント色を決めるか」が1文で言い切れているか。固定色にした場合はDESIGN_BASEの原則からの例外理由が書かれているか
- [ ] 世界観の形容詞は3つに絞られ、「やらないこと」も明記されているか

## DESIGN_BASE整合性
- [ ] 純白・純黒を使っていないか
- [ ] 角丸は12〜16の中庸帯域(カード)、8(チップ)、20(シート)に収まっているか、`.continuous`指定か
- [ ] 影はほぼゼロがベースラインになっているか(足す場合も最薄からか)
- [ ] 選択状態が「反転」パターン(墨色塗りつぶし+紙色反転)になっているか
- [ ] spring は `dampingFraction 0.7〜0.85` の帯域か、ボタン押下は `easeOut 0.18〜0.2` か
- [ ] serif/roundedの使用箇所がDESIGN_BASEの制約(紙的コンテンツのみ/局所数箇所まで)を守っているか
- [ ] すべての色・サイズ・モーションがTokens経由になっているか(hex・直書きの提案がないか)

## カラー(第2章)
- [ ] アクセントの選定根拠(配色調和関係)が説明できるか、彩度は落とされているか
- [ ] ライトモード・ダークモード両方のテーブルがあるか
- [ ] Success/Warning/Errorは本当に必要な場合のみ追加されているか

## タイポ・モチーフ(第3章)
- [ ] serif/monoを差す場所が具体的に1〜2箇所特定されているか
- [ ] モチーフは1〜3個に絞られ、それぞれ用途と一対一で紐づいているか
- [ ] テクスチャ画像・写真的表現を使っていないか

## モーション・シグネチャ要素(第4章)
- [ ] シグネチャ要素は核メタファーをそのまま動きに翻訳したものか
- [ ] 所要時間・イージング・ハプティクスが数値で仕様化されているか
- [ ] reduceMotion時の簡略版が設計されているか
- [ ] シグネチャ要素を使わない画面が明示され、静的に保たれているか

## 画面・状態・アクセシビリティ(第5章)
- [ ] CONCEPT.mdの画面一覧すべてにムードが割り当てられているか
- [ ] 主要コンポーネントの状態(Default/Pressed/Selected/Disabled/Loading/Error/Empty)が洗い出されているか
- [ ] コントラスト比・タップ領域(44×44pt)・Dynamic Type・VoiceOver・Reduced Motionが確認されているか

## AppIcon(第6章)
- [ ] モチーフが1つ(多くて2つ)に絞られ、図形だけで識別できるか
- [ ] レイヤー構成とダークモード対応が言語化されているか

## 確定プロセス(第7章)
- [ ] Artifactでのビジュアルプレビューを経てユーザーの合意を取ったか(文章だけで確定していないか)
- [ ] DESIGN.mdがテンプレート構成(0〜8節)に沿っているか
- [ ] 保存先が `Idea/ddd_アプリ名/DESIGN.md` になっているか

## つまずきの兆候(FAQ.md参照)
- [ ] DESIGN_BASEの原則とコンセプト由来の要求が矛盾したまま放置されていないか
- [ ] 「なんとなくおしゃれ」で決めた色・モチーフが紛れ込んでいないか(すべて根拠に遡れるか)

## 最終防衛線
- [ ] `adversarial-panel` スキルで敵対的レビューをかけたか(DESIGN_BASE整合性・コンセプトとの一貫性・他アプリ意匠の使い回しの有無を独立視点で検証したか)
