# 第6章: AppIcon の方向性

## ねらい

ここまでで決めた核メタファー・モチーフ・カラーを、アプリを代表する1つの図形（AppIcon）に凝縮する。ホーム画面という最も小さく、最も繰り返し見られる面での意匠の要約。

## コアフレームワーク

### モチーフを1つに絞る

第3章で洗い出したモチーフ（1〜3個）の中から、最もアプリを象徴する1つ（多くても2つの組み合わせ）だけをAppIconに使う。Nagasu の例では「波紋」＋「紙片シルエット」の2要素構成。文字・ロゴタイプは基本的に入れない（アイコン単体で識別できるシンプルな図形にする）。

### レイヤー構成を言語化する(SVG化前提)

実装（Icon Composer 等）に渡せるよう、背景から前景まで層で言語化する。

```
①背景: 紙色のフラット面(または最小限のグラデーション)
②中景: モチーフの副次要素(例: 波紋のストローク、textPrimaryの低opacity)
③前景: モチーフの主要素(例: 紙片・葉のシルエット、accent色の塗りのみ)
```

- 極端な光沢・グラデーション・立体感は付けない(DESIGN_BASEのフラット原則をアイコンでも守る)。
- ストローク(線)と塗り(面)だけで構成し、写真的・テクスチャ的表現は避ける。

### ダークモード対応

iOS 18以降のダークアイコン切替に対応する場合、背景をDESIGN_BASEのダーク背景トークンに、モチーフの色を第2章で決めたダークモードのアクセント値に置き換える。ライト/ダーク双方の構成をこの章で決めておく。

### 一元運用への接続

app-builderパイプラインでは、AppIconと同じSVG(`icon.svg`)を front/サイトやストア画像のグリフとしても使い回す方針がある(TODO.md参照)。この章で決めるレイヤー構成・配色は、後工程（`canva-image-gen`スキルでの画像生成、front/サイトのファビコン等）にそのまま渡せる形にしておく。

## 実践ステップ

1. 第3章のモチーフから、AppIconに使う1つ(多くて2つの組み合わせ)を選ぶ。
2. 背景・中景・前景のレイヤー構成を言語化する。
3. 各レイヤーの色をTokens(第2章で定義済み)から指定する。hex直書きにしない。
4. ダークモード用の構成(背景色・モチーフ色の置き換え)を決める。
5. 光沢・グラデーション・立体感を使っていないか確認する。

## チェックリスト

- [ ] モチーフは1つ(多くて2つ)に絞られているか
- [ ] 文字・ロゴタイプに頼らず、図形だけで識別できるか
- [ ] レイヤー構成(背景/中景/前景)が言語化されているか
- [ ] 各レイヤーの色が第2章のTokensから指定されているか
- [ ] ダークモード用の構成があるか
- [ ] 光沢・グラデーション・立体感を使っていないか(DESIGN_BASEのフラット原則を守っているか)

## Claudeが使うときの適用ガイド

- ユーザーが複数のモチーフを全部詰め込みたがったら、「ホーム画面で豆粒サイズになったとき、一番で認識してほしい形はどれですか」と1つへの絞り込みを促す。
- AppIcon生成の実作業は2段階で引き継ぐ: レイヤー元絵の生成(`canva-image-gen`)→`.icon`バンドルへの組み立てと検証(`icon-crafting`)。この章で決めるのはあくまで方向性の言語化であり、画像そのものの生成・組み立てはこのスキルの範囲外である。
- 「ダークモード用の構成」は`icon-crafting`側では別絵ではなく`fill`(背景)の指定に翻訳される点に注意。この章では色の置き換え先(Tokensのダーク値)まで決めておけば十分。
