# 第3章: タイポグラフィ方針とモチーフ(図形言語)

## ねらい

第1章の核メタファーを、フォントの使い分けと図形言語（アイコン・区切り線・シルエット）に変換する。DESIGN_BASE の基本方針を継承しつつ、「serif/mono/装飾をどこに差すか」というアプリ固有の判断だけをこの章で決める。

## コアフレームワーク

### タイポグラフィ: 継承と固有判断

DESIGN_BASE からそのまま継承する部分:
- 基本はシステムフォント（SF Pro）、weight は medium/semibold/bold 寄り。
- `.fontDesign(.rounded)` は使わない。
- カスタムフォントは導入しても2ファミリまで、`Font.custom` の直書き禁止（トークン経由）。

**このアプリだけで決める**のは次の2点だけである。

1. **serif をどこに差すか**: DESIGN_BASE は「紙的・文学的コンテンツにだけ」と定めている。そのアプリで「紙的・文学的」に該当する箇所（引用、記録の本文、結論の提示等）を具体的に1〜2箇所特定する。UIクローム（ボタン・ラベル・設定画面）には絶対に使わない。
2. **mono をどこに差すか**: 「数字を装飾として扱う」箇所（日付・件数・統計値）を特定する。巨大数字は Dynamic Type 非追従の固定サイズでよい。

### Type Scale とWeight階層（数値の目安）

システムフォント・Dynamic Type が基本のため、Web由来のフォントペアリング（Google Fonts の組み合わせ）はそのまま使えないが、**サイズ比率とWeight階層のロジック**は流用できる。

- サイズ階段は Major Third（比率1.25倍）を目安に、Dynamic Type の標準スケール（`.largeTitle` `.title` `.headline` `.body` `.footnote` 等）に乗せる。カスタムサイズを直書きしない。
- Weight階層: 見出し系は semibold〜bold、本文は regular〜medium、ラベル・キャプションは medium。DESIGN_BASE の「medium/semibold/bold寄り」の範囲に収める。
- 行間: 見出しはタイト（1.1〜1.3相当）、本文はゆったり（1.5前後）。日本語は文字量が多く詰まって見えやすいため、本文の行間を欧文よりやや広めに取る。

### モチーフ(図形言語)

核メタファーを、線と面だけの図形に変換する。DESIGN_BASE の「フラット＋ヘアライン」原則を、モチーフ表現でも崩さない。

- **テクスチャ画像・写真的表現を使わない**。すべて線（ストローク）と面（フラット塗り）で表現する。
- **モチーフは1〜3個に絞る**。Nagasu の例: 「水平線＋同心円の波紋」（基礎図形）「雫型」（ボタン等）「一枚の紙／葉のシルエット」（核オブジェクト）。多すぎるモチーフは装飾過多（過剰装飾の失敗パターン）に陥る。
- 各モチーフについて、**どこに使うか（アイコン/区切り線/ボタン背景/空状態イラスト等）**を一対一で紐づける。「なんとなくどこにでも使える図形」にしない。

## 実践ステップ

1. CONCEPT.md の画面一覧を見渡し、「紙的・文学的」な本文が存在する画面を1〜2箇所特定し、serif を差す場所として確定する。
2. 「数字を装飾として見せたい」箇所（サマリー・日付・件数等）を特定し、mono を差す場所として確定する。
3. 第1章の核メタファーを、線・面だけで表現できる図形に分解する（1〜3個まで）。
4. 各モチーフの用途（アイコン/区切り線/ボタン背景/空状態イラスト等）を一対一で紐づける。
5. カスタムフォント・カスタムモチーフ画像を使う場合、DESIGN_BASE のトークン経由原則（`Font.custom` 直書き禁止、SVG化前提）を満たせるか確認する。

## チェックリスト

- [ ] serif を差す場所は「紙的・文学的コンテンツ」に限定され、UIクロームに漏れ出していないか
- [ ] mono を差す場所は「数字の装飾表現」に限定されているか
- [ ] `.fontDesign(.rounded)` を使っていないか(使うとしても局所1〜2箇所か)
- [ ] カスタムフォントは2ファミリ以内で、トークン経由になっているか
- [ ] モチーフは1〜3個に絞られ、それぞれ用途が一対一で紐づいているか
- [ ] モチーフがテクスチャ画像・写真的表現ではなく、線と面だけで表現されているか
- [ ] モチーフは核メタファー(第1章)から実際に導出されているか

## Claudeが使うときの適用ガイド

- ユーザーが serif や装飾フォントを「全体的にかわいくしたい」という理由だけで使おうとしたら、DESIGN_BASE の「serif は紙的・文学的コンテンツにだけ」を伝え、具体的にどの画面のどのテキストに限定するかを一緒に決める。
- モチーフ候補が4つ以上出てきたら、「この中でコンセプトの核に一番近いものはどれですか」と絞り込みを促す。装飾を足せば足すほど DESIGN_BASE の「1点だけの遊び」から遠ざかることを伝える。
- テクスチャ画像や写真素材を使いたいという要望が出たら、DESIGN_BASE のフラット原則との矛盾を指摘し、線と面だけでの表現に翻訳できないか一緒に考える。
