# 第5章: 画面ごとのムード、コンポーネント状態、アクセシビリティ

## ねらい

ここまでで決めた色・タイポ・モチーフ・モーションを、CONCEPT.md の画面一覧すべてに配分する。「どの画面がどれだけ静かで、どこだけ主張してよいか」という温度差を明示し、UIが取りうる状態（disabled/loading/empty 等）とアクセシビリティ数値基準を漏れなくチェックする章。

## コアフレームワーク

### 画面ごとのムード指定

CONCEPT.md の画面一覧を1行ずつ確認し、各画面に「ムード」と「補足」を割り当てる。Nagasu の例のように表形式でまとめる。

| 画面 | ムード | 補足 |
|---|---|---|
| オンボーディング | 余白多め・序文的 | 大きな余白、装飾は極薄に1つだけ |
| ホーム(メイン操作) | 通常は最も静か | 装飾ゼロが基本。ただしアプリの主目的次第で例外あり |
| シグネチャ体験 | 唯一の遊びが起きる瞬間 | 第4章のシグネチャ要素そのもの |
| 一覧・アーカイブ系 | 落ち着いた一覧 | ヘアライン輪郭のみ、影なし |
| 詳細表示 | コンテンツを読ませる佇まい | 余白を広く取る |
| サマリー・統計系 | 数字だけが主役 | mono の大きな数字、装飾しない |
| 設定 | 完全に無彩 | アクセントカラーを使わない、ヘアライン・反転選択のみ |

ムードを「静か⇄主張してよい」の1本の軸で並べたとき、シグネチャ体験の画面以外はできるだけ静かに寄せる。DESIGN_BASE の「1点だけの遊び」を画面単位でも徹底する。

### コンポーネント状態の網羅(iOS向けに絞ったもの)

Web向けの状態マトリクス(Default/Hover/Active/Focus/Disabled/Loading/Error/Success/Empty State)から、iOSネイティブアプリに存在しない `Hover` を除外し、以下をチェックリストとして使う。

| 状態 | 確認すること |
|---|---|
| Default | 通常時の見た目(色・角丸・影の基本形) |
| Pressed | DESIGN_BASE の押下パターン(`scaleEffect 0.92〜0.96` + `easeOut`)を適用しているか |
| Selected | DESIGN_BASE の「反転」パターン(墨色で塗りつぶし+文字を紙色に反転)を適用しているか |
| Focused(VoiceOverカーソル) | フォーカスリングまたは相当の視覚表現があるか |
| Disabled | 不透明度を下げる(目安0.4〜0.5)、タップ不可を明示しているか |
| Loading | スピナー・スケルトン等の待機表現。DESIGN_BASE のフラット・低装飾に合った控えめな表現になっているか |
| Error | 彩度を落とした赤等、色だけに頼らずアイコン・文言でも伝えているか |
| Empty State | 「まだ何もない」ときの画面が用意されているか(Nagasuの「まだ何も流していない」画面のように、空であること自体がコンセプトを語れるかも検討) |

優先順位の目安: `disabled > loading > selected/active > focused > default`。複数の状態が重なる場合はこの順で見た目を決定する。

### アクセシビリティ数値基準

Apple HIG 由来の数値基準を必須チェックとして扱う。

- **コントラスト比**: 本文相当のテキストは 4.5:1 以上、大きな文字・アイコンは 3:1 以上を目安にする。DESIGN_BASE の暖色系配色でもこの基準は必ず満たす。
- **タップ領域**: 最小 44×44pt を確保する。モチーフや装飾でタップ領域を狭めない。
- **色だけで情報を伝えない**: エラー・成功・選択状態等は、色に加えてアイコン・文言・形（反転パターン等）でも伝える。
- **Dynamic Type**: 本文系テキストは追従させる。mono の巨大数字等、意図的に固定サイズにする箇所は理由を明記する。
- **VoiceOver**: モチーフ的な装飾要素（波紋・シルエット等）は意味を持たない場合アクセシビリティ非表示にし、意味を持つ場合はラベルを与える。
- **Reduced Motion**: 第4章の対応を画面配分の観点からも再確認する。

## 実践ステップ

1. CONCEPT.md の画面一覧を1つずつ、ムード表に転記する。
2. シグネチャ体験の画面以外がすべて「静か」側に寄っているか確認する。
3. 主要なインタラクティブ要素(ボタン・カード・チップ・選択肢)ごとに、Default/Pressed/Selected/Disabled/Loading/Error/Empty State のうちどれが必要かを洗い出す。
4. 各状態について DESIGN_BASE のパターン(反転選択・押下スケール等)を適用できるか確認する。
5. コントラスト比・タップ領域・Dynamic Type・VoiceOver・Reduced Motion をチェックリストとして通す。

## チェックリスト

- [ ] 全画面のムードが表になっているか(CONCEPT.mdの画面一覧との漏れがないか)
- [ ] シグネチャ体験以外の画面は「静か」側に寄っているか
- [ ] 主要コンポーネントの状態(Default/Pressed/Selected/Disabled/Loading/Error/Empty)が洗い出されているか
- [ ] Selected状態はDESIGN_BASEの反転パターンで統一されているか
- [ ] Empty State が用意されているか
- [ ] コントラスト比(4.5:1 / 3:1)を満たしているか
- [ ] タップ領域が44×44pt以上か
- [ ] 色だけに依存した情報伝達がないか
- [ ] Dynamic Type / VoiceOver / Reduced Motion への配慮が明記されているか

## Claudeが使うときの適用ガイド

- 画面一覧を洗い出す際、CONCEPT.mdに書かれていない画面(ローディング画面、エラー画面等)が実装上必要になりそうであれば、その場でユーザーに確認して追加する。
- 「全部の画面をにぎやかにしたい」という要望が出たら、DESIGN_BASEの「1点だけの遊び」と本章の「ムードの温度差」の両方を根拠に、シグネチャ体験以外は静かに保つよう提案する。
- Empty State が見落とされがちなので、CONCEPT.mdの画面一覧に無くても必ず確認する。
