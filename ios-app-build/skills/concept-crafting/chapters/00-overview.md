# 序章: なぜ「コンセプト」が必要なのか

## この教材の前提

AI、DX、ブロックチェーン、Web3……。流行りの技術キーワードは次から次へと現れては消えていくが、
ビジネスの本質的な問いはいつの時代も変わらない。「誰のために、何を創造するのか」。
この一点に答えを出す力、つまり新しい価値をひとつの言葉で言い当てる「コンセプト」をつくる力は、
かつては一部の経営者やクリエイターだけの特殊技能とみなされてきた。
しかし今日では、事業開発だけでなく企画・マーケティング・組織づくりなど、
あらゆる仕事に共通して求められる基礎スキルになっている。

この前提の背景には、日本のビジネスが歩んできた歴史への反省もある。長らく日本は
「良いものを安くつくる」というデフレ型の成功体験に頼り、新しく価値あるものを構想する仕事そのものを
避けてきてしまった。その結果、日本の強みは「良いものを安く」が通用する部品産業など
一部の領域に閉じ込められてしまった、という指摘がある。あらゆる産業で創造的な思考を持つ人材が
求められるようになった背景には、こうした反省がある。コンセプトメイキングはもはや起業家や
クリエイターだけの特殊な仕事ではなく、日々の仕事の中で「妄想を言語化する」力を求められる
すべてのビジネスパーソンにとっての必修基礎科目になった、というのが本書の立場である。

すでに自己流でコンセプトを書いてきた実務経験者ほど「いまさら基礎から学ぶ必要があるのか」と
感じるかもしれない。しかしコンセプトメイキングは野球の打撃フォームに似ていて、センスや我流の勘だけに
頼ると成果が不安定になりやすい。基本の型を身につけることで、誰でも一定以上の水準を安定して
発揮できるようになる、というのがこの教材の前提である。また、コンセプトを考えるうえで避けて通れない
インサイト・ビジョン・ミッション・パーパスといった関連するカタカナ概念についても、実際のつくり方を
含めて章の中で扱っていく。これらは言葉と経営を横断的に理解するための土台にもなる。

背景には産業構造の変化もある。機能やスペックで差がつきにくくなった成熟市場では、
モノや技術そのものよりも「意味」が選ばれる理由になっていく。ストックホルム経済大学の
ロベルト・ベルガンティ教授が提唱する「意味のイノベーション」という概念がこの転換をよく説明している。
電球の発明によって「暗がりをなくす」というロウソクの機能的役割はとうに終わったはずなのに、
ロウソクは2000年代以降も多くの先進国で売り上げを伸ばし続けている。名前を「キャンドル」に変え、
「あたたかい雰囲気をつくるもの」「香りを楽しむもの」として生き残り、なかには最先端のLED電球よりも
はるかに高額な製品まで存在する。この価値の逆転現象は、技術的な先進性だけをイノベーションと呼ぶ
発想では永遠に説明がつかない。同じ転換は、これから多くの商品・サービスで起こる。
だからこそ、まだ形になっていないアイデアを的確な言葉で先取りし、仲間や決裁者、投資家を動かす
「コンセプトを書く力」が実務上の武器になる。

言葉が先にできる、という順序も重要な前提である。世界にまだない商品やサービスをつくろうとするとき、
それを的確に言い当てる言葉もまた、まだ世の中に存在しない。語ることができなければ、思考を深めることも、
仲間と議論することも不可能だ。つくる人は、なにより先に言葉をつくることになる。センスや感性が
重要とされるジャンルであっても、この原則は変わらない。「一枚の布」というコンセプトから世界的な
服づくりを続けるファッションブランドや、業界の不透明な価格設定や環境負荷を可視化する
「徹底的な透明性」を掲げて若い世代の支持を集めたアパレルブランド、黒子だった調香師をブランドの
主役に据えて「香りの出版社」を名乗ることでマンネリ化した香水業界に新風を吹き込んだ香水ブランド、
そして「まちに開かれた公園のような美術館」という言葉から、どの方向からも通り抜けられる裏側を
持たない建築が実現した美術館。ジャンルを問わず、優れたつくり手はまず言葉というプロトタイプを
つくり、そこから形を起こしていく。デザインや図面などビジュアルが決定的な役割を果たす業界でさえ、
その本質部分の設計は言葉が担っているのである。図面や試作品よりも先に、
コンセプトという1円もかからない試作品が必要になる。

コンセプトメイキングは日々の実務の生産性にも直接効いてくる。機能するコンセプトを一度つくることが
できれば、曖昧だったアイデアが仲間に明確に伝わるだけでなく、コンセプトそのものが口の端に乗って
自分が参加していない社内外の会議まで一人歩きし、新たな発想を誘発するようになる。簡潔で芯を捉えた
提案を求める決裁者へのプレゼンの成功率も上がり、その先ではマーケティングの起点にもなって、
広告や商品という姿に変わって生活者のもとに届いていく。投資家がお金に働かせるように、
企画者はもっと言葉に働かせるべきだ、というのがこの発想の核心である。忙しくて新しいアイデアに
取り組む時間がないという人ほど、実はこの意味でコンセプトを学ぶメリットが大きい。

この型は、化粧品や家電、IT企業の新規事業、スタートアップなど、開発スタイルも業種もまったく異なる
現場でコンセプトメイキングを重ねてきた経験から抽出されたものである。研究所での新技術の意味づけから、
生活者観察を起点にしたプロトタイピング、創業者個人の想いを起点にした事業ビジョンの構築、
そして事業成長に合わせた迅速な言葉の更新まで、必要になるアプローチはそのつど異なっていた。
それでも共通する原理原則を抽出し、長年にわたって多くの受講生からのフィードバックを重ねて
アップデートされてきた研修プログラムが、この型のベースになっている。

多くの人はコンセプトづくりをセンスや才能の問題だと誤解しているが、実際には手順として学べる
「型」がある。苦手意識を持っているとしたら、それはセンスがないからでも才能がないからでもなく、
単に型を知らないだけである。ただし型にも限界はある。手順通りに考えれば恥ずかしくないコンセプトは
書けるようになるが、型だけですべてがうまくいく魔法のツールは存在しない。もしいつか型の限界に
ぶつかることがあれば、それは相応の技術を身につけた証拠であり、逆説的にこのスキルの役割は
果たせたことになる。このスキルは、その型を使って漠然としたアイデアを鋭いコンセプトへ
磨き上げるためのものであり、以下の6章はその型を分解して並べたものである。

型を身につけると、新しいことを企む作業がいま以上に楽しくなる。そのままなら誰にも相手にされない
妄想であっても、説得力のあるストーリーや一行のフレーズになった瞬間、周囲の反応は変わる。
一緒に実現したいという人や、投資したいという人が現れ、やがてユーザーやファンがついてくる。
コンセプトという名の設計図が現実に変わっていく、その感覚を一度でも味わってもらうことが、
このスキル最終的な狙いである。

## 6章の全体像

全体は、アイデアを一直線に磨き上げていく制作プロセスとして構成されている。

- **第1章 コンセプトとはなにか？**
  コンセプトの定義と、良いコンセプト・悪いコンセプトを見分ける条件を扱う。
  以降のすべての作業で使う「ものさし」を、ここでユーザーと共有する。
  頭で理解するだけでなく、他人に説明できる状態を目指す章である。

- **第2章 コンセプトを導く「問い」のつくり方**
  答えより先に「問い」を立てることの重要性を扱う。問いの立て方次第で見える景色は変わってしまうため、
  行き詰まった問いを立て直す「リフレーミング」の技術をここで学ぶ。
  第3章・第4章のストーリー設計は、この章で立てた問いへの回答として展開される。

- **第3章 顧客目線で設計する「インサイト型ストーリー」**
  問いへの答えを、顧客の中にある心理的な葛藤(インサイト)を起点にした物語として組み立てる方法を扱う。
  すでに顧客や生活者が見えている案件で威力を発揮するアプローチである。

- **第4章 未来目線で設計する「ビジョン型ストーリー」**
  同じ問いに対して、企業や創業者が描く理想の未来像から逆算して物語を組み立てる、もう一つのアプローチ。
  まだ顧客像や技術用途が定まっていない、初期段階の事業や新規性の高い構想で有効になる。
  インサイト型と組み合わせることで、コンセプトに奥行きが生まれる。

- **第5章 コンセプトを「1行化」する**
  第3章・第4章で組み立てたストーリーを、鋭く記憶に残る一行のフレーズへ圧縮する技術と、
  使える構文パターンを学ぶ。「言葉のセンス」と呼ばれてきたものが、
  実は再現可能なスキルであることが分かる章である。

- **第6章 コンセプトを「最適化」する**
  出来上がった一行を、商品・サービス開発／マーケティングコミュニケーション開発／
  組織のコンセプト開発という3つの実務文脈それぞれに合わせて調整する方法を扱う。
  同じ一行でも、耐用年数や適用範囲によって磨き方が変わることを学ぶ。

流れを一言で言えば「問いを立てる → ストーリーを設計する → 一行に凝縮する → 文脈に合わせて最適化する」。
各章は前の章の成果物を材料にして次へ進む構造になっているため、
基本的には第1章から順番に進めるのがもっとも効果が高い。
ただし進行中の案件がある場合は、第1章で共通認識だけ作った後、必要な章から拾い読みしても構わない。

なお第2章以降の各章には、実際に手を動かして考えるための「ミニワーク」が用意されている。
目安の制限時間が示されているが、10分で切り上げてもよいし、粘りたければ何日かけて取り組んでも構わない。
時間の目安はあくまで目安であり、頭と手を実際に動かしながら読み進めることが重要になる。

## このスキル全体の使い方

Claude Codeがユーザーの漠然としたアイデアをコンセプトに仕上げる会話をする際は、
以下の順序で `chapters/` を参照する。

1. **ユーザーがいまどの工程にいるかを見極める。** 発言から次の目安で判断する。

   - まだ思いつき・課題感の段階で、何が「良いコンセプト」かの共通認識もない → 第1章から始める。
   - アイデアはあるが「誰のどんな悩みを解決するのか」が曖昧 → 第2章で問いを明確にしてから第3〜4章へ進む。
   - ターゲットの心理的な葛藤や不満は見えているがストーリー化されていない → 第3章(インサイト型)。
   - 技術シーズや創業者の思いが先行していて、顧客像より先に理想の未来像から逆算したい → 第4章(ビジョン型)。
   - ストーリーはできているが長くまとまらず、一言で言えない → 第5章。
   - 一行のコンセプトはあるが、資料や現場でうまく機能しない、文脈に応じて調整したい → 第6章。

2. **迷ったら第1章の基準を軽く共有してから進める。**
   ユーザーが「これは良いコンセプトか」を自己判断できる土台を先に作っておくと、以降の工程がぶれにくくなる。

3. **各章は独立した読み物ではなく、前工程の答えを材料として渡す前提で書かれている。**
   後の章を参照する際は、ユーザーが前の章のワークで出した答え(問い・インサイト・ビジョンなど)を
   一緒に持ち込んで使う。前の工程が固まっていないのに後の章に飛ぼうとしていたら、
   一度差し戻す判断も必要になる。

4. **ユーザーが誤解でつまずいていそうな場合は `FAQ.md` を参照する。**
   「センスの問題だと思い込んでいる」「KPIだけで十分だと思っている」
   「型通りにやったのに平凡な言葉しか出てこない」といったつまずきは典型的なパターンなので、
   そこで軌道修正の一言を添えてから作業を続ける。

5. **本書の解説をそのまま語るのではなく、実際に手を動かす方向に誘導する。**
   このスキルはダイジェストを読ませるための資料ではなく、
   ユーザーと一緒に問い・ストーリー・一行を実際に書き上げるためのワークブックとして使う。
   章の説明を長々と話すより、章が提示する問いかけやワークをユーザー自身の題材にあてはめて
   答えてもらうことを優先する。

6. **最終的なゴールを見失わない。**
   目指すのは書籍の内容を正確に説明することではなく、
   ユーザーの漠然としたアイデアが、他人に伝わり、周囲を動かす一行のコンセプトに変わることである。
   章を進めるたびに、その一行に近づいているかを都度確認する。

7. **各章に登場する実例は、原理を学ぶための一例として扱う。**
   紹介される実例は「目新しさ」より「評価が確立していること」を優先して選ばれているが、
   時間が経てば評価が変わったり、当初の文脈とは違う方向へ展開したりすることもありうる。
   実例そのものを丸暗記させることに意味はなく、その実例が体現している原理原則を
   ユーザー自身の題材に当てはめて考える、という使い方を徹底する。
