# 最終診断リスト

コンセプトが完成したとユーザーに提示する前に、以下を横断チェックする。各項目の詳細は元になった章を参照。

## 定義・基礎(第1章)
- [ ] WHAT(なにを)ではなくWHY(なぜ存在するか)を語っているか
- [ ] 顧客目線で書けているか(送り手都合のスペック語りになっていないか)
- [ ] 「ならでは」と言えるか(同じ言葉で競合や他ジャンルまで説明できてしまわないか)
- [ ] ビジネス目標に見合うスケールの顧客層を捉えているか
- [ ] 一度聞いただけで理解・記憶・伝達できるシンプルさか
- [ ] 声に出して語ったとき、話す本人の熱量が上がるか

## 問い(第2章)
- [ ] 出発点の「問い」は自由度とインパクトを両立した良問になっているか(悪問・クイズ・愚問に陥っていないか)

## ストーリー(第3・4章)
- [ ] インサイトは「AだけどB」の矛盾を含む構文で書け、「言われてみたら、そうかも!」の手応えがあるか
- [ ] 4つのC(Customer→Competitor→Company→Concept)が「しかし/そこで/つまり」で無理なくつながるか
- [ ] ビジョンを使う場合、コンフォートゾーンに収まらずストレッチゾーンにあるか
- [ ] インサイト型とビジョン型、両方の筋道が同じコンセプトに収束しているか(矛盾がないか)

## 1行化(第5章)
- [ ] 1行に含まれる概念は2つ以内に収まっているか
- [ ] 声に出して3回、噛まずに言えるか(3回テスト)
- [ ] 手垢のついた予測変換的な言葉に留まっていないか

## 最適化(第6章)
- [ ] 用途(商品・サービス開発/マーケティング文/組織バリュー)に応じた型を正しく選べているか
- [ ] ベネフィットとファクト(根拠)が対で書かれているか

## つまずきの兆候(FAQ.md参照)
- [ ] 用語の定義論争に時間を使いすぎていないか
- [ ] KPIだけで十分だと思い込んでいないか
- [ ] 手順通りにやったのに平凡な結論で満足していないか(ユーザー自身の違和感・こだわりを材料にできているか)
- [ ] バズワードの羅列で中身を誤魔化していないか

## 最終防衛線
- [ ] `adversarial-panel` スキルで敵対的レビューをかけたか(「ならでは」の主張・競合との差別化・4条件充足を独立視点で検証したか)
