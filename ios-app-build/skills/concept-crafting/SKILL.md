# コンセプトづくり支援 (concept-crafting)

## 概要

漠然とした思いつきを、「誰のために・なぜ存在するのか」を一言で言い当てる鋭い「コンセプト」に仕上げるための実践ワークフロー。問いを立て直す→顧客目線・未来目線でストーリーを設計する→1行に凝縮する→実務の型に最適化する、という一直線の制作プロセスを、各工程のフレームワーク・実践ステップ・チェックリストとして提供する。

## 全体ワークフロー

基本は上から順に進める。ただし進行中の案件がある場合は第1章で判断基準だけ共有し、必要な章から拾い読みしてよい。

> **第2章（問いのつくり方）に入る前に `/last30days <テーマ>` を回すと精度が上がる。**
> 直近30日の Reddit / Hacker News / YouTube の実発言を engagement 順で返す（API キー不要）。
> インサイト（第3章）は本来「顧客の心理的葛藤」を要求するが、そこを想像で埋めると平凡な結論になる
> （FAQ.md の指摘どおり）。実際に投稿された不満・言い回しを一次資料として持ち込む。

1. **[00-overview.md](chapters/00-overview.md)** — 序章。なぜ今コンセプトが必要か、6章の全体像、このスキル自体の使い方。最初に読むべき索引。
2. **[01-concept-basics.md](chapters/01-concept-basics.md)** — 第1章: コンセプトとはなにか？ 定義と、良いコンセプトを見分ける4条件。すべての工程で使う「ものさし」。
3. **[02-framing-questions.md](chapters/02-framing-questions.md)** — 第2章: コンセプトを導く「問い」のつくり方。答えを急がず、リフレーミングで良問を立てる。
4. **[03-insight-story.md](chapters/03-insight-story.md)** — 第3章: 顧客目線の「インサイト型ストーリー」。顧客の心理的葛藤(インサイト)から4Cでストーリーを組む。
5. **[04-vision-story.md](chapters/04-vision-story.md)** — 第4章: 未来目線の「ビジョン型ストーリー」。ミッション→ビジョン→コンセプトの時間軸でストーリーを組む。
6. **[05-one-line.md](chapters/05-one-line.md)** — 第5章: コンセプトを「1行化」する。3点整理法・2単語ルール・10の構文で一行に圧縮する。
7. **[06-optimization.md](chapters/06-optimization.md)** — 第6章: コンセプトを「最適化」する。商品開発/マーケティング文/組織バリューへの落とし込み方。

補助資料:
- **[FAQ.md](FAQ.md)** — よくある質問・つまずきポイント(用語の混同、KPI偏重、平凡な結論になる原因など)。
- **[CHECKLIST.md](CHECKLIST.md)** — 全工程を横断した最終診断リスト。コンセプトを完成として提示する前の最終ゲート。

## どの章を参照すべきか(診断表)

| ユーザーの状態 | 参照する章 |
|:---|:---|
| まだ思いつき段階で、「良いコンセプト」の共通認識もない | 01 から開始 |
| アイデアはあるが「誰のどんな悩みを解決するか」が曖昧 | 02 → 03/04 |
| 顧客の不満・葛藤は見えているがストーリー化されていない | 03(インサイト型) |
| 技術シーズや創業者の思いが先行し、理想の未来から逆算したい | 04(ビジョン型) |
| ストーリーはできたが長く、一言で言えない | 05 |
| 一行はあるが、資料や現場でうまく機能しない | 06 |
| 用語の混同・KPI偏重・平凡な結論などでつまずいている | FAQ.md |

## 使い方の原則

- **一緒に手を動かす場であって、要約を読ませる場ではない。** 各章の解説をそのまま語るのではなく、実践ステップに沿って質問を投げ、ユーザー自身に書かせる。
- **前工程の成果物を次工程の材料にする。** 章ごとに独立した読み物ではないため、後の章を使うときは前の章で出した答え(問い・インサイト・ビジョンなど)を一緒に持ち込む。
- **迷ったら第1章の基準に立ち返る。** 「顧客目線か」「ならでは、と言えるか」「シンプルか」の3条件は全工程に共通する判断軸になる。
- **コンセプトが完成したと思ったら [CHECKLIST.md](CHECKLIST.md) で最終確認する。** 各章のチェックリストのうち特に重要な項目を横断でまとめてある。
- **CHECKLIST.md を通ったら `adversarial-panel` スキルで敵対的レビューにかける。** 「ならでは、と言えるか」「競合と本当に差別化できているか」は、書いた本人には見えにくい。1行コンセプトと差別化の主張を独立した視点で殴り合わせてから、ユーザーに完成として提示する。
